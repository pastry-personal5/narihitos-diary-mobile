# Product behavior

Status: Active

Product scope: the v1 behavior confirmed by the owner. Details still needing a decision are linked below.

## Confirmed v1 behavior

### Target and recording

- V1 targets iPhone 17 Pro Max running iOS 27.0.1 or later, without iPad support.
- On first launch, explain why recording needs the microphone and request microphone permission. If permission is denied, let the user continue using non-recording parts of the app; the Record control explains how to enable the microphone in system Settings. Recording begins only after permission is granted.
- A user can record up to five minutes of audio without a network connection.
- At five minutes, stop recording and queue the finalized audio automatically. If an audio interruption ends recording early, automatically queue a playable partial recording. If the partial file cannot be played, retain it in Failed Recordings and show the reason beside its entry.
- The app may keep the recording temporarily in private local storage while offline or while its iCloud destination is unavailable.
- A user provides an en-US or ko-KR recording language hint where possible. Store the user's hint with the recording, pass a corresponding value to a transcription method when supported, and save only this hint as the asset language value.

### Transcription

- V1 offers Apple on-device transcription and an on-device Cohere Transcribe method derived from [CohereLabs/cohere-transcribe-03-2026](https://huggingface.co/CohereLabs/cohere-transcribe-03-2026) or a suitable English/Korean Cohere variant. Reuse the last selected method; if it is not ready, keep the job waiting and ask the user to install its model or choose another ready method. Provide method readiness and model-download controls in Settings. The Cohere method runs locally after its model is installed and does not upload recordings for transcription. The exact conversion, runtime, and download design require target-phone validation before implementation.
- The Settings screen lets a user preflight Apple on-device transcription, download a needed language model, wait for readiness, and see the reason when it is unavailable. If Apple transcription is unavailable for a queued recording, ask the user to choose among available approved methods; never switch automatically.
- A queued recording uses the transcription method and method settings selected when processing starts. Record the method, model or conversion, and settings actually used with the result. If a local model is missing or not ready, keep the job pending and offer model installation or selection of another ready approved method; never switch methods automatically.
- Transcription runs automatically, oldest ready recording first, only while the app is open. A waiting or failed recording does not block a newer ready one. Each processing attempt settles its own job before the queue advances; a failed job does not retry automatically or hold the worker. A hung local inference must be bounded or cancelled, retaining audio and an entry-level failure reason before other ready work proceeds. Recordings and queue state survive offline periods and app closure. Request notification permission and schedule a local reminder for the next local day at the same local time the user left the app when pending work remains; show pending state in the app as well.
- A v1 transcription failure keeps the audio in a failed queue state and offers manual retry; local model unavailability keeps the job pending with a reason. Create no diary Markdown until transcription produces usable text.
- A manual transcription retry uses the method and settings current when the user starts that retry. Manual retries have no fixed count limit while the recording remains.
- If transcription yields no usable words, retain the audio as a failed recording, create no asset, and offer manual retry. Show the reason beside the entry in Failed Recordings.
- Allow the user to remove a pending or failed recording and its private audio after confirmation. Removal must stop or invalidate any processing of that recording so it cannot later create an asset. For an in-flight recording, show Cancelling until work stops and removal completes.
- Transcription output initializes the diary's single managed text body. Prefer an Apple on-device AI summary of the whole body for its read-only title when the model is available; if the model is unavailable or returns an empty or failed result, shorten the body's first sentence locally with an ellipsis. Both title paths have a strict 30-displayed-character maximum, counting any ellipsis within the limit. Save the Markdown and audio asset automatically without a pre-save review step, including after an AI title failure. User edits replace the body; regenerate the title using the same policy on save. An emptied body may be saved with the title "Untitled". Do not keep a separate original transcript after the managed text is written.
- Generate an AI title in the current diary body's language, even if that differs from the recording's language hint. If the generated title uses the wrong language, use the first-sentence fallback. If the body exceeds one on-device model request's context window, summarize it in parts and combine those summaries into a title. Truncate an overlong AI title locally to the 30-character limit with an ellipsis rather than asking the model again. Once saved, a fallback title stays in place when the model later becomes ready; the next body save regenerates it.

### Assets and metadata

- Diary Snippet is the only confirmed v1 asset type. The architecture allows other asset types later, but their behavior is not defined here.
- Show the existing Markdown/audio pairs that lack the new schema fields as read-only Diary Snippets; leave their files untouched.
- V1 stores assets in a user-selected iCloud folder. The user may select any iCloud folder or create one. Local and third-party folders are outside v1.
- Before the first recording, require the user to select or create an iCloud destination folder. If a pending recording's original folder becomes permanently inaccessible, allow the user to explicitly choose a replacement for that recording.
- Changing the selected folder leaves existing assets in the old folder. The app lists only assets in the active folder.
- Main shows the full active-folder diary collection with on-demand loading and infinite scroll. A one-line notice bar at its top reports queued recordings, in-app transcription, and recovery attention, rotating one message every 10 seconds when several apply. Rotation pauses for VoiceOver or Reduce Motion; queued and processing messages open Pending Recordings, and a recovery message opens its relevant recovery screen. All shows no diary snippets for now. Settings opens only from All, and a floating Record control is on Main.
- Pending Recordings, Failed Recordings, Incomplete Diary Snippets, and Conflicting Versions are separate screens opened from All. The two recovery screens contain incomplete pairs and equal-time or missing-time conflicts respectively; Main shows only notice-bar attention for them. Diary Snippet detail shows Title and Diary body first, Favorite beside Title, and Audio replay inside bottom Metadata. Metadata also shows read-only recording start date/time, duration, language hint, and available place and weather, omitting unavailable optional values.
- During capture, Stop & Transcribe is the only user control; it stops and queues playable audio for automatic processing while the app is open. Pause/resume and discard controls are outside v1. The exact v1 empty-state messages are “Benefits are coming later.”, “Calendar is coming later.”, and “Plugins are coming later.” No Main Toolbar is specified.
- A recording keeps the iCloud destination folder selected when recording began, even if the active folder changes before processing finishes. If that destination is unavailable, keep the result pending and ask the user to restore access. When a result is saved into a former active folder, show a completion notice naming that folder.
- If a recording's destination is temporarily unavailable, continue local transcription and prepare the managed diary text, then keep the private draft pending until it can be saved.
- The Markdown body is the only managed diary text. Its automatically generated title is read-only. The editor changes only the body; Favorite has a separate on/off toggle. Record, Stop & Transcribe, Settings, Pending Recordings, Failed Recordings, Incomplete Diary Snippets, Conflicting Versions, and Favorite are exact v1 labels.
- Include the generated title and its AI, fallback, or empty-body origin in Markdown front matter, along with a schema version and explicit audio filename reference. For an AI title, record the Apple model version when identifiable, the iOS version, and the title-prompt revision; omit an unavailable model-version identifier rather than guessing it. Keep title-generation provenance in the file without showing it on the asset detail screen. Record the effective transcription method and, where applicable, model, region, and context there as provenance.
- Set `created_at` to the instant recording started and group assets by that instant's date in the user's local calendar. Set `updated_at` when a saved text or metadata edit occurs; an iCloud sync or download alone does not change it. File and directory names remain UTC as required by [AGENTS.md](../AGENTS.md).
- Location and weather are optional, permission-based metadata describing the time of recording. Request location permission during first launch and provide a Settings control for later permission changes; denial does not block recording. When location is available, save exact latitude/longitude and a place name. If either location or recording-time weather is unavailable, create the asset and omit its unavailable front-matter fields. Do not backfill missing weather later.
- Recorded-audio replay offers play/pause, seeking, and elapsed and total time.
- For conflicting iCloud edits with comparable modification times, make the later version current automatically and discard the older version. Device clock differences can make timestamp order differ from actual edit order.
- If conflicting versions have equal or missing iCloud modification times, keep both and show one version per vertically scrollable tab in Conflicting Versions. The user chooses one; confirm before removing the other. If an iCloud write leaves an incomplete Diary Snippet bundle, repair it from the retained local candidate when the app reopens. If no retained local candidate exists, keep the incomplete files and flag the item in Incomplete Diary Snippets; show whichever diary text or playable audio survives read-only, explain what is missing, and offer removal only after confirmation.
- If saving a completed diary draft fails because iCloud access is unavailable, retain its private Markdown and audio files and retry saving them automatically when access returns, without repeating transcription. Delete the private staging folder immediately after the complete iCloud pair is verified.

### Future work: hosted Qwen transcription

Hosted Qwen transcription is outside v1. Earlier owner decisions remain recorded for a future release: the user supplies a key stored in Keychain until removed, chooses Beijing or Singapore and supported model controls, and consents before audio upload. Consent revocation deletes the key; key removal fails pending Qwen jobs while retaining audio. A user-set budget blocks requests that would exceed this app's estimated monthly usage and resets at the start of the user's local calendar month. Only temporary network or server transcription failures receive up to three automatic retries. These controls and cloud jobs are not shown or created in v1.

Remaining title details and the schema, provider, and failure rules are tracked in the [P1-M1 decision inventory](research/p1-m1-open-decisions.md). Planned screen behavior is in [UX GUI](ux-gui.md).
