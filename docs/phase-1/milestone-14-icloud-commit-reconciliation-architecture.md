# P1-M14: iCloud commit and reconciliation approach

Status: Planned

This plan adds a coordinated external-pair store and a resumable save coordinator behind the existing destination and queue boundaries. Durable local evidence, not an in-memory callback or filename, controls completion and cleanup.

## Boundaries and commit record

The application coordinator consumes a verified M13 draft handle, a leased audio handle, the current queue claim, and opaque destination access. Its ports expose typed pair-write, pair-read, upload-observation, snapshot, and cleanup outcomes; domain/application code receives no URL, bookmark, `NSFileCoordinator`, or provider error. The platform adapter alone resolves the original capture snapshot, balances security scopes, coordinates access, validates file identities and containment at use time, and maps provider failures to sanitized states. The M7 codec validates Markdown and references; the M9 audio verifier supplies actual playable-source identity.

Extend the versioned per-job record with an app-owned commit intent: stable asset ID and UTC pair names derived from the verified draft, source Markdown/audio lengths and cryptographic digests, attempt/generation, installation binding, destination/body revisions, original destination snapshot reference, and the exact external identities/versions observed during creation or repair. Store only bounded identity evidence, never an arbitrary deletion path or a front-matter hash as authority. Migration leaves old jobs readable and cannot invent commit success. Keep the retained M13 draft binding and audio available throughout verification.

## Publication and upload proof

1. Reconcile tombstones, restore quarantine, and the verified draft/audio claim. Recheck the claim after every asynchronous operation; destination availability is a save prerequisite, not a prerequisite for local transcription or draft creation. Snapshot the original destination and current revisions. A changed active folder has no effect.
2. Acquire the M10 per-job mutation barrier before the first destination mutation and retain ownership through pair verification, upload proof, and durable completion. Resolve the recorded destination with M8's positive iCloud/account checks. Bound provider waits; a timeout leaves ownership uncertain until coordination actually relinquishes work. A removal or retarget accepted first invalidates this save attempt.
3. Persist the commit intent before writing. Coordinate each resource. Validate parent and final target without following an unsafe reference. Create the expected audio exclusively, then the Markdown, or replace only an exact version already owned by this commit. Write into provider-coordinated temporary targets where supported and publish with checked identity; never use unchecked overwrite or infer ownership from a matching asset ID. If either write fails, retain private staging and the observed partial state.
4. Reopen both files through coordinated reads, decode the Markdown, check its explicit audio filename and canonical layout, verify the actual audio and both expected lengths/digests, and record the observed file identities/versions. A file changed after the write is a conflict or recovery item. A complete pair that matches an earlier intent is reused rather than written again.
5. Observe upload success independently for the two exact versions just verified. Recheck their identities and bytes if observation was interrupted or provider state changed. Missing or ambiguous status means `Waiting for iCloud upload verification.` and `Retry Verification`; a destination outage uses `Waiting for access to {folder}.` and `Restore Access`. These states do not block other ready jobs. The physical iPhone prototype must establish the platform signal for a user-picked folder; no local-file, sync-indicator, elapsed-time, or network-availability substitute counts as proof.
6. Recheck claim and versions, durably record verified completion, then remove only the job-owned private staging and release its destination snapshot. An interrupted cleanup resumes from recorded completion without reopening a write path. If the queue store cannot persist proof, retain staging and reverify later. If cleanup cannot finish, retain a cleanup-pending state and retry; do not describe private deletion as complete. Emit the former-folder banner event only after durable completion.

## Reopen, repair, and conflicts

Reconciliation inspects each job independently before scheduling. A matching complete pair resumes at local/upload verification. An owned audio-only or Markdown-only pair can be repaired from the retained candidate only if the commit intent, current job revisions, external file identities/versions, and expected bytes all agree. If no candidate remains, preserve and flag the surviving files. External edits, unsafe references, unknown schemas, duplicate IDs in different resources, provider version uncertainty, or mismatched ownership stop automatic repair and cleanup. A queue-store failure pauses durable advancement; it never turns an observed file into a completed job.

Snapshot each complete conflict candidate as a protected, backup-excluded Markdown/audio pair with its own verified binding and observed iCloud modification time. Validate each pair and its referenced audio before applying the approved time rule. A later comparable time wins automatically; equal or missing times stay separate for M17's user choice. Do not combine Markdown from one candidate with audio from another. Publish and verify the chosen pair, including required upload proof for a new write, before deleting an obsolete external version or private snapshot. Revalidate exact resource identity/version immediately before deletion; changed or shared resources stay in recovery. M16's editor passes its read version to this same expected-version/conflict port; M17 owns presentation and choice confirmation.

## Verification sequence

1. Add typed commit intent and store ports, queue migration, and a fake coordinated provider. Test one successful save, active-folder changes, waiting jobs, and duplicate IDs without adding a dependency.
2. Implement the platform coordinator behind M8's destination access. Inject failures at intent persistence, each file write, reopen, both upload reports, completion persistence, and staging cleanup; relaunch after each point.
3. Add version-checked repair and protected pair snapshots. Test equal/missing/comparable times, shared audio, unsafe references, external mutation between observation and deletion, removal/retarget races, and bounded coordination that never falsely acknowledges settlement.
4. Run affected tests while iterating, then the full lint and simulator gate once. On a target iPhone, execute [M14-D01–M14-D07](milestone-14-icloud-commit-reconciliation-device-evidence.md), recording only redacted state, version class, timing, and evidence method. A missing per-file upload signal or failure of the M8 folder identity predicate requires owner review before changing the approved outcome.
