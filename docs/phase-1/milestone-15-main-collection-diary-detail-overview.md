## Review refinements and implementation prerequisites

- **Ordering:** raw descending filenames do not implement the approved timestamp/ID order, especially across whole-second and legacy millisecond names. Use the normalized ordering and resumable metadata discovery in the [approach](milestone-15-main-collection-diary-detail-architecture.md#candidate-discovery-and-paging); prove the next range before publishing it.
- **Bounded work:** 50 candidates alone does not bound directory discovery, audio decoding, provider waits, or retained bodies. The approach separates discovery progress from collection results and requires streaming, cancellation settlement, and disposable summary-only state. Empty pages with continuation are not an empty collection.
- **Legacy evidence:** resolved on 2026-11-02 by the owner's supplied examples. The [evidenced format contract](milestone-15-legacy-format.md) records the timestamp-only IDs/names, offset timestamps, empty-tags spelling, and independent audio names using synthetic values. The reader does not invent v1 UUIDs or metadata for legacy files; tests never load personal examples.
- **Existing adapter gaps:** M14's `DiaryRecoveryInspectionPort.inspectActive` currently uses a capture-snapshot loan, and `DiaryExternalPairStatus.blocked(String)` cannot distinguish unsupported content, provider waits, and conflicts. M15 needs its own active-selection fence and typed catalog outcomes; reusing these components unchanged does not meet this plan. Preserve M14's capture-time destination semantics.
- **Handoffs:** keep resource identity separate from observed version; one resource's new version replaces its old projection, while distinct resources sharing an asset ID remain ambiguous. Detect unresolved provider conflicts before presenting a finished entry. Include stored-context formatting and weather attribution in M15 presentation rather than deferring required attribution to M18.

The checklist below is the implementation gate; earlier device evidence remains open. ## Scope

- Add a type-neutral `AssetCatalogPort` and registered Diary Snippet catalog adapter. Keep destination URLs, bookmarks, provider errors, and file-system cursors outside Domain/Application and expose opaque, version-bound catalog handles to presentation.
- Enumerate only the positively revalidated active iCloud folder. Examine at most 50 coalesced candidates per request, including discovery/classification work and orphan `.assets` survivors. Return explicit progress, retry, and end states. Use normalized recording instants descending, stable asset/catalog IDs ascending, then resource identities ascending for collisions; group loaded entries in the user's current local calendar. Directory indexing yields incrementally and cannot assume sorted provider enumeration. There is no total collection cap.
- Decode new-schema Markdown with M7's bounded codec, require the canonical resource layout, and inspect the referenced audio through coordinated, non-following access. Validate actual size, AAC/M4A format, decodability, and decoded duration before marking audio available. Revalidate identity and bytes when detail opens; an earlier page result is not playback or mutation authority.
- Add a bounded legacy reader for the fixture-backed pre-v1 contract established above, including its existing millisecond names, without treating a malformed v1 document as legacy. A legacy Markdown file with exactly one safe plausible audio sibling appears read-only on Main under an ephemeral path-based identity with a separate observed version and is never normalized or rewritten. Its presentation-only title reuses the approved bounded first-sentence fallback and is never persisted. Its body remains inert; audio over 64 MiB, longer than 60 minutes, or not decodable is unavailable while safe text remains readable. Zero or multiple plausible siblings become typed recovery items.
- Classify malformed known-v1, unsupported, unsafe, incomplete, duplicate-ID, ambiguous legacy, and unresolved provider-conflict resources as typed read-only recovery projections without hiding another resource or stopping later candidates. Reuse M14's incomplete-pair values where applicable, enriching catalog outcomes instead of parsing reason strings; M17 must not need to reinterpret raw provider state. Temporary access/download failures remain retryable rather than becoming malformed or missing-file claims.
- Invalidate an active catalog session, every cursor, and in-flight result when the active destination or iCloud identity changes. Provider change notifications invalidate affected pages/details; foreground refresh and retry recover from temporary access loss. A stale callback cannot repopulate the new folder, and disappearance during a read is never treated as deletion authority.
- Replace Main's placeholder with an on-demand collection, local-date sections, stable loading/empty/error states, and type-safe navigation to `Diary Snippet`. Keep the floating English and Korean Record controls clear of list content and system safe areas.
- Add the one-line Main notice bar. It derives semantic processing, queued, and known recovery states from durable queue/catalog projections; shows one at a time; rotates every 10 seconds in that order; pauses whenever VoiceOver or Reduce Motion is active; announces each new semantic state politely without timer chatter; and routes queued/processing to Pending Recordings and recovery to the relevant M17 destination.
- Build read-only Diary Snippet detail with heading `Diary Snippet`: Title and a noninteractive current Favorite state beside it, then inert native Diary body, then bottom Metadata for recording start, duration, language hint, and available place/weather values. Show coordinates when place lookup failed, format temperature with the system measurement locale, and include Apple Weather attribution beneath any displayed weather. Keep title provenance hidden, omit unavailable optional values, and expose typed audio availability for M16 without adding playback authority. Legacy detail has no Favorite or editing action.
- Replace temporary system symbols for the five root tabs, Record/Stop, Settings, pending, warning, incomplete, and conflict affordances with the approved monochrome template bitmap sets at 1x/2x/3x. M16 retains Favorite/play/pause/seek control art. Preserve system tint, outline/filled state discipline, 25 pt tab art, 24 pt inline art, 32 pt Record/Stop art, and at least 44-by-44-point targets.
- Verify inert rendering, privacy-cover timing, diagnostics, bounded work, accessibility, and responsiveness with synthetic files only. Test light/dark appearance, small and large iPhones, landscape, the largest Dynamic Type sizes, VoiceOver order/announcements, Reduce Motion, and provider-driven refresh.

## Out of scope

M15 does not edit or rewrite any Diary Snippet, toggle Favorite, play or seek audio, acquire location/weather, schedule reminders, repair or remove external resources, choose a conflict version, retarget pending work, change the schema, add a provider/dependency, or merge assets from former folders. It does not turn a catalog cache, asset ID, filename, or successful read into write/delete authority.
