# P1-M15: Main collection and Diary Snippet detail overview

Status: Planned

Build the active-folder Diary Snippet catalog and a safe read-only detail experience, with bounded paging, legacy discovery, Main notices, and accessible final navigation/recording artwork. Keep mutations and recovery actions in their assigned later milestones.

## Entry and locked inputs

- Follow [Phase 1 order](phase-1.md): implementation follows P1-M14 completion unless the owner authorizes a reorder. Planning does not close M14's target-iPhone provider evidence or any earlier open device gate.
- Use the [P1-M5 schema and interface contracts](milestone-05-decisions-architecture.md), [M7 codec and layout](milestone-07-asset-storage-architecture.md), [M8 active-destination capability](milestone-08-first-launch-settings-icloud-architecture.md), and [M14 external-pair classification](milestone-14-icloud-commit-reconciliation-architecture.md). Preserve the approved [catalog consistency](../architecture.md#catalog-consistency), [UX containment](../ux-information-architecture.md), and [untrusted-content boundary](../architecture.md#file-access-and-untrusted-content).
- The active folder is the sole Main collection source. A recording's former capture folder, pending private work, recovery snapshots, and conflict candidates never enter Main merely because the app can access them.
- M15 owns read-only catalog/detail projections and recovery attention. M16 owns body editing, Favorite mutation, and audio replay. M17 owns complete Pending/Failed/Incomplete/Conflict recovery presentation and actions. M18 owns optional-context acquisition and pending-work reminders. M19 owns complete-experience adversarial validation.

## Scope

- Add a type-neutral `AssetCatalogPort` and registered Diary Snippet catalog adapter. Keep destination URLs, bookmarks, provider errors, and file-system cursors outside Domain/Application and expose opaque, version-bound catalog handles to presentation.
- Enumerate only the positively revalidated active iCloud folder. Examine at most 50 candidate layout stems per page, coalescing a Markdown resource and matching or orphan `.assets` directory as one candidate. Sort supported entries by `created_at` descending, stable asset/catalog ID, then resource identity for collisions; group the loaded entries by the recording-start instant in the user's current local calendar. There is no total collection cap.
- Decode new-schema Markdown with M7's bounded codec, require the canonical resource layout, and inspect the referenced audio through coordinated, non-following access. Validate actual size, AAC/M4A format, decodability, and decoded duration before marking audio available. Revalidate identity and bytes when detail opens; an earlier page result is not playback or mutation authority.
- Add a bounded legacy reader for the documented pre-v1 header/body and millisecond-name shape without treating a malformed v1 document as legacy. A legacy Markdown file with exactly one safe plausible audio sibling appears read-only on Main under an ephemeral path/version identity and is never normalized or rewritten. Its presentation-only title reuses the approved bounded first-sentence fallback and is never persisted. Its body remains inert; audio over 64 MiB, longer than 60 minutes, or not decodable is unavailable while safe text remains readable. Zero or multiple plausible siblings become typed recovery items.
- Classify malformed known-v1, unsupported, unsafe, incomplete, duplicate-ID, and ambiguous legacy resources as separate read-only recovery projections without hiding another resource or stopping later candidates. Reuse M14's incomplete-pair type where applicable; M17 must not need to reinterpret raw provider state.
- Invalidate an active catalog session, every cursor, and in-flight result when the active destination or iCloud identity changes. Provider change notifications invalidate affected pages/details; foreground refresh and retry recover from temporary access loss. A stale callback cannot repopulate the new folder, and disappearance during a read is never treated as deletion authority.
- Replace Main's placeholder with an on-demand collection, local-date sections, stable loading/empty/error states, and type-safe navigation to `Diary Snippet`. Keep the floating English and Korean Record controls clear of list content and system safe areas.
- Add the one-line Main notice bar. It derives semantic processing, queued, and known recovery states from durable queue/catalog projections; shows one at a time; rotates every 10 seconds in that order; pauses whenever VoiceOver or Reduce Motion is active; announces each new semantic state politely without timer chatter; and routes queued/processing to Pending Recordings and recovery to the relevant M17 destination.
- Build read-only Diary Snippet detail with heading `Diary Snippet`: Title and the current Favorite state beside it, then an inert native rendering of Diary body, then bottom Metadata for recording start, duration, language hint, and available place/weather values. Keep title provenance hidden, omit unavailable optional values, and expose verified audio availability for M16 without adding playback. Legacy detail is entirely read-only.
- Replace temporary system symbols for the five root tabs, Record/Stop, Settings, pending, warning, incomplete, and conflict affordances with the approved monochrome template bitmap sets at 1x/2x/3x. M16 retains Favorite/play/pause/seek control art. Preserve system tint, outline/filled state discipline, 25 pt tab art, 24 pt inline art, 32 pt Record/Stop art, and at least 44-by-44-point targets.
- Verify inert rendering, privacy-cover timing, diagnostics, bounded work, accessibility, and responsiveness with synthetic files only. Test light/dark appearance, small and large iPhones, landscape, the largest Dynamic Type sizes, VoiceOver order/announcements, Reduce Motion, and provider-driven refresh.

## Out of scope

M15 does not edit or rewrite any Diary Snippet, toggle Favorite, play or seek audio, acquire location/weather, schedule reminders, repair or remove external resources, choose a conflict version, retarget pending work, change the schema, add a provider/dependency, or merge assets from former folders. It does not turn a catalog cache, asset ID, filename, or successful read into write/delete authority.

## Completion checklist

- [ ] A registered type-neutral catalog boundary pages only the revalidated active folder through opaque session/item handles; Domain/Application receive no URL, bookmark, provider error, or file cursor. A synthetic second asset-kind registration proves browsing/open routing without changing Diary Snippet or queue rules.
- [ ] Each request examines at most 50 coalesced layout candidates, including orphan Markdown or `.assets` survivors, returns a deterministic continuation without a total cap, orders supported entries by `created_at` descending, stable asset/catalog ID, then resource identity for collisions, and groups loaded entries by the user's current local date. Large folders load incrementally with stable loading, retry, empty, and end states.
- [ ] New-schema entries require bounded codec success, canonical Markdown/audio layout, safe coordinated containment, and actual audio size/format/decoded-duration validation. Detail reopens the exact observed version; mutation, disappearance, unsafe references, digest mismatch, oversized input, or decoder failure preserves the files and returns a typed unavailable/recovery outcome.
- [ ] Legacy discovery is bounded and read-only, cannot downgrade malformed v1 into legacy, and uses only the existing first-sentence fallback for its nonpersisted display title. Exactly one safe plausible sibling produces an ephemeral Main/detail entry without any file write; zero or multiple siblings produce explained recovery items; unsafe references never open; and audio beyond 64 MiB/60 minutes or failed decoding leaves safe text readable with audio unavailable.
- [ ] Unsupported, malformed, incomplete, unsafe, duplicate-ID, and ambiguous resources are isolated as version-bound recovery projections and do not block later page candidates. Repeated observation of the same resource/version deduplicates; distinct resources claiming one asset ID remain separate and cannot hide each other.
- [ ] Active-folder/identity changes cancel and fence page/detail work, clear disposable projections, and prevent stale results from entering the new collection. Coordinated provider notifications and foreground refresh invalidate affected content without treating a transient read failure as deletion or searching another folder.
- [ ] Main renders the full on-demand collection, local-date sections, floating English/Korean Record controls, and a one-line notice bar. Notice order, 10-second rotation, VoiceOver/Reduce Motion pause, polite deduplicated announcements, and Pending/recovery routing match the approved UX; All remains the sole Settings/recovery hub.
- [ ] `Diary Snippet` detail renders Title and current Favorite state first, inert Diary body second, and bottom Metadata with approved read-only fields and omission rules. Title provenance is hidden, legacy detail has no mutation controls, and a typed verified-audio handle/availability is ready for M16 without shipping replay.
- [ ] Approved custom template bitmaps replace M15-owned temporary symbols with correct scale variants, sizes, tint/state behavior, and semantic accessibility. Light/dark mode, safe areas, small/large iPhone layouts, landscape, maximum Dynamic Type, VoiceOver order, Reduce Motion, 44-point targets, and the nonforeground privacy cover pass visual/accessibility checks.
- [ ] Adversarial tests cover traversal/links/swap races, malformed and oversized text/audio, duplicate IDs across pages, stale cursors/callbacks, folder changes, provider failures, inert Markdown/HTML/URLs, bounded diagnostics, and continuation after a bad item. No content, path, location, bookmark, or raw provider error appears in logs or evidence.
- [ ] The [target-iPhone evidence record](milestone-15-main-collection-diary-detail-device-evidence.md) has redacted pass evidence for M15-D01–M15-D08, including user-picked-folder paging/refresh, legacy/audio behavior, accessibility/layout, privacy, and notice routing.
- [ ] Affected user/architecture/UX docs describe the implemented handoffs. `make lint` and `TEST_DESTINATION=… scripts/validate.sh` pass with the destination recorded; if a required command cannot run, this item remains unchecked with the blocker reported.
