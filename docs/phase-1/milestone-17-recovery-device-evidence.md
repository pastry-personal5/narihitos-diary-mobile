# P1-M17: Pending, failed, incomplete, and conflict recovery device evidence

Status: Draft

Record target-iPhone evidence for recovery screens and their durable actions after implementation. Use disposable synthetic English/Korean recordings, diary pairs, and controlled iCloud accounts; no physical scenario has been run for this plan.

## Run record

For each scenario, record device/iOS/app revision, owner class (recording, external resource, submitted edit), synthetic size/language/duration class, provider/account availability class, relevant operation/fault boundary, observed typed result, settlement/upload/cleanup evidence, and evidence method. Separate passed, failed, blocked, and partially run observations; a partial run does not close a row. Confirm deletion/account-change test setup uses only explicitly disposable fixtures before executing it.

Do not commit bodies, audio, titles/model output, coordinates, folder names/paths, account/provider identifiers, bookmarks, prompts, or raw logs/screenshots containing them. Use sanitized operation/reason codes, counts, timings, and opaque local references. Simulator and fake-adapter results supplement these observations without replacing them.
