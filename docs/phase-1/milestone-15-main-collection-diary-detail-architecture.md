# P1-M15: Main collection and Diary Snippet detail approach

Status: Active

Add a generation-fenced active-folder catalog behind Clean Architecture ports, then project validated summaries and read-only details into Main. External files remain untrusted, reads grant no mutation authority, and presentation state remains disposable.

## Source boundaries and composition

Keep type-neutral catalog values/use cases in Domain/Application, active-folder coordination and file/audio decoding in Adapters, and list/detail/notice state in Presentation. Register kind-specific discovery/summary/detail validators in an adapter-side catalog registry and kind-specific detail renderers in a separate presentation registry at the composition root. Application routes carry kind IDs and opaque handles, never SwiftUI views or decoder implementations. Diary Snippet v1 and its legacy reader are the only shipped handlers; a synthetic second-kind fixture proves discovery and open routing without a global Diary Snippet switch or its directory shape. This is static registration, not a runtime plugin feature.

The application-facing `AssetCatalogPort` exposes operations equivalent to:

- begin/refresh/end the current active-folder session;
- load one bounded page from an opaque cursor;
- reopen an exact observed item/version for detail or read-only recovery; and
- publish typed invalidation/access/recovery events.

Use three distinct identities. `CatalogSessionID` fences destination, iCloud identity, and catalog generation. A session-local resource key identifies one observed location independently of its claimed asset ID; legacy uses an ephemeral path-based key. An observation handle binds that resource to its exact file/pair version and registered handler. Row identity can stay stable when a resource's version changes, while an old detail handle becomes unusable. Cursor/handle values are bounded opaque tokens, not serialized paths, URLs, provider identifiers, or deletion instructions. Adapter mappings and directory indexes are session-local and contain no retained bodies/audio; do not persist a content-bearing catalog cache in M15.

## Candidate discovery and paging

Walk only plain directories beneath the active root without following aliases, symbolic/hard links, packages, or unexpected resource types. The Diary handler recognizes the UTC year/month/day hierarchy and validated current/fixture-backed legacy stems; another registered kind supplies its own discovery strategy. Coalesce a Markdown resource and matching `.assets` directory as one candidate, including either orphan. Do not count the two components as separate assets or recurse into audio directories as additional assets. Ignore unrelated ordinary files for presentation while counting enumeration work against a cancellable discovery slice. A malformed layout-shaped resource becomes recovery attention without opening an unsafe target; it cannot disappear merely because v1 name parsing fails.

### Ordering and continuation

The collection order is recording instant descending, stable asset/catalog ID ascending, then session resource key ascending. Parse timestamp components into an instant; never sort raw mixed-precision stems. For example, an accepted legacy instant at `.500` precedes a current whole-second instant in that same second, and equal-time UUIDs use ascending order. Canonical v1 body metadata must reproduce the discovered timestamp/layout before acceptance; legacy agreement follows its established fixture contract. A mismatch is recovery, not an out-of-order accepted entry.

Build ordered metadata indexes for the directories needed to establish the next range, yielding during enumeration. A provider's enumeration order is not a sorted index. Finish the necessary sibling metadata discovery before claiming a range is the newest remaining one; normalize and merge candidate keys across handlers, formats, and equal-time boundaries. Do not eagerly read/decode every body/audio file to sort the folder. Prove this ordering frontier with shuffled enumeration and a very large single-day directory. If provider ordering requires broader metadata discovery, show explicit discovery progress rather than a false empty result or a blocking main-thread scan.

Each request performs at most 50 candidate visits across discovery and classification, not 50 successes plus unlimited rejected entries. Enumeration of unrelated files and directories also has a named internal work/time slice and yields with continuation. Metadata indexing may revisit a candidate in a later classification slice; it cannot hide a full scan inside one request. The cursor stores only a token for session-owned continuation/frontier state. Returns distinguish:

| Page outcome | Meaning for presentation |
|---|---|
| Results with continuation | Merge summaries/recovery observations; more work remains. |
| Progress with continuation and no entries | Discovery or an all-recovery slice advanced; remain loading, not empty/end. |
| End | This generation's traversal completed; only now may a zero-entry collection be empty. Recovery attention remains available. |
| Item unavailable | Preserve a retryable observation and continue other candidates; retry that resource separately. |
| Session unavailable / refresh required | Pause/restart under a fresh fenced loan; never reuse a foreign/stale cursor. |

Progress must advance a cursor or return a typed wait, never return the same cursor repeatedly in an automatic loop. There is one page request at a time, driven only by a visible collection needing results; stop prefetch on inactivity/navigation away. Many malformed/unrelated resources cannot spin a foreground loop or prevent cancellation. There is no total collection cap. Metadata indexes/summaries may grow with the browsed collection; bodies and decoded audio do not. Memory pressure can discard the session and require fresh traversal, never silently truncate the collection.

### Observation, invalidation, and collisions

Attach resource identity and content/version observations from coordinated reads, not cached URL metadata alone. Identical resource/version observations deduplicate. A new version of the same resource replaces its old summary/recovery projection and invalidates any open detail; it is not an additional item. Distinct resources claiming one v1 ID remain distinct: remove both from the finished Main collection, expose both as ambiguous recovery, and invalidate an already open detail. This works even when the duplicate appears several pages later. Counts describe observed resources, not an exhaustive folder count before traversal ends.

Provider notifications invalidate affected items and ordering indexes, or the whole session when a change cannot be localized. Insertions/removals ahead of the cursor cannot leave a supposedly complete traversal missing entries. Coalesce bursts and refresh on foreground as a backstop; no elapsed-time heuristic proves identity. A transient failure never proves deletion. Only a successful refreshed enumeration can remove a vanished disposable projection, without mutating source files. Regroup original instants with `Calendar.autoupdatingCurrent` on local date/calendar/timezone changes. Former-folder completion drives only M14's banner; active-folder completion requests refresh rather than injecting private draft data.

## Bounded I/O and session lifetime

Do discovery, hashing, decoding, and formatting preparation off the main actor; publish only fenced value results on the main actor. Enforce byte limits while reading as well as before reading. Stream audio with bounded decode buffers and frame/duration checks, never whole-file PCM or allocations derived from an untrusted declared duration. Use named internal enumeration, provider, and decoder budgets with cooperative cancellation. Exhausting a work slice yields progress; unavailable provider proof yields retryable state rather than changing approved format/size/duration limits. Bound legacy sibling enumeration too: discovery must finish before asserting exactly one candidate, and finding two permits an immediate ambiguity result.

Reuse the existing coordinator's cancellation/settlement rules; its current 15-second recovery-read timeout is a starting point for provider attempts, not proof that a complete legacy decode fits that budget. Establish a separate measured bounded decoder budget or resumable streaming strategy against the longest accepted fixture so a valid 60-minute file cannot repeatedly time out by construction. Wait for every accessor to settle before releasing security scope. Cancellation is not settlement. Invalidate results immediately on selection/account change, inactivity, or memory-pressure teardown, remove observers, and discard projections; physically release loans/mappings only after accessors relinquish them. Permit only one unsettled catalog operation at a time, so retries cannot accumulate stalled coordinators/scopes. A stuck cancelled operation leaves a typed unavailable state while unrelated recording/queue/UI work continues. Record this platform limitation if it cannot settle; do not claim an exact cancellation deadline or start unlimited replacement attempts. On reentry, revalidate the current folder and begin a fresh generation when settlement allows it.

## Current-schema and legacy classification

### Current schema

1. Open bounded UTF-8 Markdown with coordinated non-following access. Apply M7's 64 KiB front-matter, 1 MiB body, 64-key, and 8 KiB scalar rules, including streaming byte-growth checks.
2. Require supported codec output and an ID/`created_at` reproducing the exact canonical Markdown name, assets directory, and explicit audio filename. Unknown schema/kind/method/title origin is unsupported; malformed known-v1 data is malformed. Neither is rewritten or passed to legacy decoding.
3. Open audio only after checking every component and final resource, including after provider resolution. Require a plain file up to 64 MiB, actual AAC/M4A format and complete bounded decodability, and positive decoded duration no longer than 301 seconds. Check any declared audio digest against actual bytes. Reach a clean decoder end; truncated data cannot pass because its prefix plays. Use frame-based boundaries rather than rounded display time; do not impose exact capture bitrate on external audio without an approved rule.
4. Recheck both resources after decoding and before returning a finished pair, including unresolved-conflict state; observations from different pair revisions cannot be combined. Detail reopens that exact pair and repeats checks. M16 must acquire a fresh verified audio lease for playback; an M15 availability flag conveys no long-lived URL or authority.

Reuse M14's typed incomplete-pair values for canonical layouts, but keep missing, changed, unsupported, unsafe, and temporarily unavailable outcomes distinct. A download/access timeout is retryable, not proof of a missing sibling. Required v1 audio that is missing/invalid leaves recovery with safe surviving content, not a finished Main entry. Nothing discovered by the catalog authorizes repair or removal.

### Legacy

The owner resolved the [legacy evidence prerequisite](milestone-15-legacy-format.md) on 2026-11-02. Use that evidenced contract and its synthetic fixtures. The approved pairing decision does not establish that every old header has v1 UUIDs, `updated_at`, or whole-second timestamps. Document the evidenced accepted grammar and synthetic golden fixtures before implementing it; unsupported variants stay preserved pending owner review rather than broadening a heuristic parser.

Use the same text byte/key/scalar bounds and reject executable YAML features, duplicate keys, unsafe references, and ambiguous parsing. Do not construct YAML objects or reinterpret ignored fields as authority. A document claiming `schema_version` or `kind` goes through current/unsupported classification and cannot downgrade to legacy. Use an ephemeral path-based resource key with a separate observed version. Derive its display title with M13's pure bounded first-sentence fallback, without AI, provenance writes, or a new title limit.

Enumerate safe plausible audio siblings according to the evidenced format. Exactly one permits read-only Main/detail; zero/multiple means explained Incomplete Diary Snippets recovery. A single audio file exceeding 64 MiB/60 decoded minutes or failing decoding leaves safe text readable with audio unavailable. Unsafe siblings are never followed, cannot establish safe unique pairing, and yield explained read-only recovery. Legacy never reaches the v1 encoder, AI title generator, editor, Favorite writer, or commit store. Compare source bytes and app-controlled metadata before/after reads; provider-internal download/sync changes are not claimed to be app rewrites.

### Recovery handoff

Return a typed reason code, observed resource/version handle, safe surviving-content availability, and an existing All destination. Unsupported/malformed/incomplete/unsafe/duplicate/legacy-ambiguous items route to Incomplete Diary Snippets. Unresolved provider versions route to Conflicting Versions, separately from duplicate IDs. Detect conflicts even without a local pending job; current bytes alone must not appear as finished while conflict state is unresolved. Reuse M14 whole-pair validation/snapshot mechanics through read-only ports where applicable; never guess pairings, parse display reasons, or invoke version selection/deletion from catalog reads. Preserve unpairable versions with a typed reason for M17.

Queue-derived Failed and Pending attention use those destinations, including former-folder work, without inserting content into Main. M15 supplies typed routes and read-only placeholder destinations with correct headings until M17 completes screens/actions. Catalog handles permit reopen only. M16/M17 must separately revalidate versions, destination, ownership, and mutation authority at action time.

## Detail and inert content

Project full detail only after exact-version reopen. For v1 it includes saved Title, noninteractive Favorite state, body, recording start, duration, stored language hint, validated optional context, and typed audio availability. Exclude title provenance and uninterpreted scalars. Legacy has no mutation capability; do not fabricate a Favorite value or missing metadata. A replaced/invalidated resource clears stale body behind a changed/unavailable state and requests refresh, rather than silently opening replacement bytes under an old navigation handle.

Render with verbatim native text or a restricted native Markdown subset. Remove link attributes/actions, automatic data detection, HTML/script execution, attachments, remote images, and fetches; URL-looking text stays text. Test HTML, images, Markdown links, custom schemes, and long Unicode/control input. Do not place content in accessibility identifiers, persisted navigation, logs, or diagnostics. Normal accessibility reading of visible content remains available. Keep summaries across pages and only the current bounded detail body; clear detail when closed. The neutral privacy cover precedes every nonforeground snapshot, including notices and the former-folder banner.

Reading order is Title/current Favorite state, Diary body, then bottom Metadata. Show Favorite as state text with appropriate semantics in M15, not a disabled imitation toggle; M16 adds action/art. Format recording start in the current locale/timezone, duration with locale-appropriate components, and language from the stored hint without redetection. Omit unavailable/invalid optional groups. Show accepted coordinates when place lookup failed, format stored Celsius in the system measurement locale, and include Apple Weather attribution beneath displayed weather. M15 owns this stored-context presentation/attribution handoff; M18 adds acquisition. Establish attribution availability through the existing dependency boundary before displaying weather; missing attribution remains an integration requirement, not permission to ship unattributed weather. Browsing triggers no context lookup/backfill. M16 later adds replay controls inside Metadata after acquiring a fresh lease.

## Main presentation and notices

Use a native lazy list with local-date sections and resource-based row identity. Model initial discovery, loading, loaded-with-continuation, end, no-folder, access-unavailable, and retry separately. An all-recovery folder has no finished snippets but retains recovery attention. Keep available rows during same-session transient refresh only when clearly stale and unable to open without validation; folder/account changes clear them immediately. Main has no second Settings entry: access/selection navigation goes through All's existing Settings destination.

Keep one in-flight page request and stable scroll/focus anchors. Trigger next-page work near the tail; progress-only slices continue only while results are needed and yield between slices. Loading exposes busy semantics without stealing VoiceOver focus or shifting prior rows. Preserve existing recording gates and 56 pt `en`/`ko` controls in a bottom safe-area inset. No Main Toolbar is added.

Build `MainNoticeState` from durable semantic projections, not display strings or one raw count:

1. active transcription while the app is open;
2. queued/pending work, excluding active transcription from its count; and
3. known recovery attention with a specific Pending/Failed/Incomplete/Conflict route.

Show one bounded visual line with a complete accessibility label. With multiple states, rotate every 10 seconds in processing/queued/recovery order. Visit multiple recovery destinations deterministically on successive recovery turns so none starves. Stop the timer for VoiceOver, Reduce Motion, inactive scene, or invisible notice. Restart at highest priority when the semantic set changes, not on every count/progress update. Announce newly introduced semantic states once, politely; ticks, count changes, and foreground reentry alone do not reannounce unchanged states. A removed state may announce if it returns. Taps use the displayed state's route, then select All and open that destination. Use an injected clock for tests. The separate dismissible six-second former-folder banner must not cover the notice/Record/focused row or reset notice timing.

Replace M15-owned temporary symbols with checked-in monochrome template bitmaps. Own the five tabs, Record/Stop, Settings, pending, warning, incomplete, and conflict artwork; M16 owns Favorite/play/pause/seek. Keep labels independent of filenames and decorative art out of duplicate speech. Verify 1x/2x/3x sharpness, system tint in both appearances, 25/24/32 pt art, outline/filled discipline, 44 pt targets, and pressed/disabled/selected semantics. Check 4.5:1 normal-text and 3:1 meaningful-icon contrast. A notice can truncate visually at accessibility sizes while exposing its full message; Title/body/Metadata wrap without horizontal scrolling. Smaller simulator widths are layout checks, not a change to the iPhone 17 Pro Max product target.

## Implemented mechanisms and handoff (2026-11-02)

`AssetCatalog` supplies the application values/port and summary-only collection reducer. `CatalogAssetRegistry` registers discovery/read handlers independently of `CatalogDetailRendererRegistry`. `AppleAssetCatalog` owns the active selection, one unsettled operation, observer lifecycle, and epoch fences; `FileCatalogWorker` owns disposable ordered metadata, cursors, and exact-version observations. The current implementation establishes ordering through resumable metadata discovery before reading bodies, then yields classification after at most 50 candidates or a two-second soft page budget. Metadata discovery may span the selected folder; its progress is explicit and no full-folder body/audio scan precedes the first content page.

`CatalogDirectoryCursor` retains the native directory stream in the adapter session: a `telldir` cookie cannot be transferred to a reopened stream. Every slice runs within a fresh active-folder loan and revalidates directory identity/version with descriptor-relative traversal. Session teardown drops its cursors only after active accessors settle; no descriptor or provider cursor crosses the application boundary. Numeric unsafe/package directories become recovery attention rather than being followed. The metadata attempt budget is 15 seconds; pair/decode work has a cooperative 120-second budget and 4,096-frame mono decode buffers. Coordinator cancellation never claims settlement of a still-running accessor.

`DiaryCatalogReadPlan` first discovers confined targets using metadata-only coordination, then coordinates the exact Markdown/audio file contents together. Directory coordination alone is insufficient for child content reads; see Apple's [coordinated-read guidance](https://developer.apple.com/documentation/foundation/nsfilecoordinator/coordinate(readingitemat:options:error:byaccessor:)). Resolved targets must match the confined paths, and the decoder refuses audio absent from that plan. `CatalogSafeFiles` uses non-following `openat`, validates regular-file/link counts, enforces streaming bounds, and rejects FIFOs without blocking. `CatalogAudioInspector` decodes a confined descriptor through AudioToolbox callbacks, checks actual container/codec/frame bounds and clean end, hashes bytes, and checks identities again. Legacy unique-sibling reads additionally bind the assets-directory version. Safe text survives missing/invalid/unsafe audio as a read-only value or typed recovery; no reader writes source files.

Presentation uses a lazy native list, current-calendar sections, a body rendered with `Text(verbatim:)`, a separate current detail, and semantic notice state. Same-folder recovery attention survives foreground refresh without repeated announcements; changing destination/account clears that scope. A changed detail closes its stale route and refreshes; duplicate-ID attention cannot be bypassed with the detail Retry action. Main's folder recovery action opens All, keeping the Settings entry there. A saved active-folder pair refreshes the catalog; a former-folder save uses the separate banner.

`WeatherAttributionPort` separates the presentation model from WeatherKit/networking in `AppleWeatherAttributionSource`. That adapter fetches only Apple's attribution material, with bounded ephemeral image reads; it receives no diary, recording, or coordinates. The displayed weather requires the official appearance-specific mark and legal link supplied by [WeatherAttribution](https://developer.apple.com/documentation/weatherkit/weatherattribution). If material is unavailable, show a truthful attribution-retry state rather than unattributed weather. M18 still owns context acquisition.

The [overview evidence](milestone-15-main-collection-diary-detail-overview.md#implementation-evidence-2026-11-02) records passing automated checks and the remaining physical-device gate. M16 must obtain fresh edit/playback capabilities, and M17 must obtain action-time ownership/confirmation; catalog reads do not grant either.
