### Demonstrated readiness defect and repair

Apple distinguishes system asset installation from an app's locale reservations. [`AssetInventory`](https://developer.apple.com/documentation/speech/assetinventory) states that installed assets persist across launches and are shared between apps, while [`reservedLocales`](https://developer.apple.com/documentation/speech/assetinventory/reservedlocales) contains the current app's reservations and is required before subscribing to locale-specific assets. Speech exposes `assetLocaleNotAllocated` for a module whose locale is not allocated. The app nevertheless mapped `AssetInventory.Status.installed` directly to `.ready`; `AppleAssetInstaller.prepare` then returned `.ready` and skipped the only path that calls `reserve(locale:)`. An asset installed by the system, another app, or an earlier configuration could therefore appear ready before SpeechAnalyzer rejected the module as unallocated.

The repair requires both conditions. Installed plus reserved remains Ready. Installed but unreserved is the typed `.reservationRequired` state, presented as `Setup required` with a `Set Up English/Korean Model` action. That action reuses the approved installer: it resolves the exact recording language, reserves it without releasing another locale, asks `assetInstallationRequest(supporting:)` to reconcile the already-installed module, and reports Ready only after a fresh status and reservation check. Apple preflight uses the same readiness source, so an unreserved locale remains unclaimed rather than failing after claim. Cohere is unchanged.

The deterministic regression sets the platform state to installed while reservation is false and observes `.reservationRequired`; the immediately preceding installed-plus-reserved control observes `.ready`. Installer coverage proves the setup state reaches reservation, accepts a nil installation request for an already-installed asset only after the backend becomes truly ready, and never fabricates a download. Presentation coverage proves the new truthful status copy.

### Demonstrated capture-boundary defect and repair

The continuing phone trace reached `SpeechAnalyzer`, but its verified input contained only AAC encoder priming: 960 frames / approximately 22 ms for every reported and controlled capture, including captures whose UI ran for tens of seconds. Both microphone permission surfaces were granted, `AVAudioRecorder` remained recording with an advancing clock, and forcing the available built-in input did not alter the result. The zero-result stream and unusable-text collector were therefore correct downstream outcomes, not an Apple result-thread race.

`AppleCaptureEnvironment` previously called `prepareToRecord()`, then changed backup exclusion and data protection on the recorder's open destination, then called `record()`. The repaired lifecycle completes the private-file mutations before encoder preparation and records only after both succeed. `AppleAudioRecorderStart` makes this ordering deterministic and testable; a preparation failure cannot call `record()`. A physical-device gate on the same phone records and decodes more than one second of AAC and re-verifies both attributes, while the pre-fix production path repeatedly finalized only the 960-frame payload. Receipt inspection, immutable leases, Apple output validation, and all Cohere paths remain unchanged.

The 2026-11-03 phone start failure exposed a missing precondition in that repair: the production workspace returned an output URL without creating the file. `protectOpenAudio` requires a regular file, and the thrown Cocoa 260/POSIX 2 error confirmed that the file was absent. Create it exclusively in the prepared workspace, protect it, then initialize and prepare the recorder; reject an existing output rather than replacing it. The first updated phone attempt started but still produced only 960 decoded frames. The follow-up changes post-initialization protection to read-only verification, but the second phone attempt had the same empty AAC result. Apple documents that [`prepareToRecord()`](https://developer.apple.com/documentation/avfaudio/avaudiorecorder/preparetorecord%28%29) creates or overwrites the output file, so file existence after recorder initialization is not a valid precondition. A source-level ordering test is useful for the start failure, but only a device test can establish that the resulting AAC carries speech frames.
