# P1-M20: Enhancements, fixes, and refactoring approach

Status: Active

Investigate and repair owner-reported behavior through small, verifiable changes. The first task traces iCloud folder selection and the shared private Settings store after an app reinstall. A second planned task introduces dedicated Transcription Settings and explicit local model choices. A third planned task isolates why Main reports an already accepted folder as unavailable after recording. A fourth planned task traces a Cohere-selected English recording that is reported unreadable alongside the Main failure.

## Boundaries and approved inputs

- `ContentView`, `SettingsView`, `FolderPicker`, and `AppModel` own picker/disclosure presentation and the displayed active-folder state.
- `AppleDestinationService` owns prepare/commit generation fencing, scope balancing, iCloud validation, bookmark resolution, identity checks, and transactional destination acceptance.
- `PrivateSettingsRepository` owns the bounded private Application Support record shared by onboarding, destination selection, and transcription-method settings.
- Preserve [M8's selection and persistence contracts](milestone-08-first-launch-settings-icloud-architecture.md), Clean Architecture's inward dependency rule, and the existing capture/queue destination bindings. UI dismissal never grants access or proves a successful save.

## Investigation and implementation sequence

1. Trace a fresh-install selection from the picker callback to disclosure presentation, acceptance, commit, and active-folder publication. Inspect dismissal and scene/identity ordering for a lost or superseded prepared selection. Distinguish a validation failure, presentation failure, persistence failure, and subsequent reload failure.
2. Inspect Settings directory creation, initial reads, bounded decoding, atomic writes, in-memory publication, and reload. Verify that saving one setting preserves the others and that errors retain prior committed data. Use synthetic fixtures and sanitized outcomes rather than private user data.
3. Add focused behavioral regressions for the demonstrated failure before changing production behavior. Use the existing destination-platform fakes and a temporary private Settings directory; include real repository save/reopen coverage rather than relying only on a successful fake save.
4. Fix the failing boundary with targeted changes. Keep disclosure acceptance explicit and the destination unpublished until its complete record is durably saved. Preserve generation fencing, positive iCloud validation, balanced scopes, and old-selection retention.
5. Delegate affected checks and first-pass failure analysis to `test_runner`, then run the required lint and simulator gate. Resolve implementation failures in the main thread and record exact validation limitations.
6. Update the overview with root-cause evidence and redacted verification. Verify the first-install selection and relaunch on the target iPhone when accessible; keep that item open if the phone or Files/iCloud interaction is unavailable.

## Verification and limits

Tests must exercise actual state transitions and disk round trips, including failure preservation. Source inspection can identify a missing handoff or unsafe storage behavior but cannot prove the real phone's Files provider metadata, security-scope behavior, account identity, or bookmark survival. No validation failure permits weakening the approved iCloud-only predicate or replacing the user's destination automatically.

Task 1's implemented handoff and Settings storage repair are described in the [architecture](../architecture.md#ui-and-application-state) and [M20 evidence](milestone-20-enhancements-fixes-refactoring-overview.md#evidence); physical Files/provider verification remains open.

### Navigation and model details

Use Settings → group `Transcription` → card `Transcription` → item `Transcription` → screen titled `Transcription`. Group/card/item describe one grouped navigation row, not three intermediate screens. Its summary shows the saved model label and readiness; opening it never selects or installs anything. Move existing Apple/Cohere controls into the child and keep Active Folder and Location in parent Settings.

The child contains `AI Models` with exactly the four choices below, followed by model details. Normal Settings shows details for the saved selection and allows persisting an unready preference. Contextual Pending/Failed Recordings → Choose Method opens this same child in All's navigation, preserves the affected language, and retains M11's ready-for-that-language selection requirement. In recovery, inspecting another model changes only the temporary detail focus; the saved-choice checkmark stays unchanged until an explicit ready-only use action succeeds. None/unready choices can therefore expose reasons/install actions without being applied. The choice remains global for both languages, not a per-recording override. A failed recording still requires its explicit Retry action. Clear recovery context only when that route is exited or superseded, not when parent Settings disappears to push the child.

| Choice | Selection token → method | Details and actions |
|---|---|---|
| `None` | `none` → no adapter | Explain that recordings can still be queued and wait for an explicit model choice. No install action. This controls transcription only, not Apple title generation or completed drafts. |
| `Apple Local` | `apple-local` → `ndm.transcription.apple` | Separate English/Korean readiness, supported installation actions, progress/cancel, and sanitized reasons. Recovery emphasizes the affected language without guessing or changing it. Retain system reservation behavior; do not invent model IDs, download sizes, or storage estimates. |

| `Cohere Q5` | `cohere-q5` → `ndm.transcription.cohere` with `Q5_K_M` | The same categories from Q5's own descriptor and install state. No accuracy/speed superiority claim; readiness requires its own verified artifact. |

Installation and selection are separate intents. Selecting never downloads; installation completion never changes selection. If installation continues for an unselected variant, retain a small, clearly named operation status/cancel row outside the selected-model details so it remains discoverable. No user-facing uninstall or additional tuning parameters are introduced. Keep native grouped forms, semantic selected state beyond color, named progress values, 44-point actions, Dynamic Type, light/dark contrast, and stable VoiceOver focus. Reduce Motion must not hide status updates. Hide runtime hashes, paths, and raw errors from product flows.

### Durable selection and upgrade

Add a typed `selectedTranscriptionModel` field using the stable tokens in the table; keep provider IDs unchanged in adapters, jobs, and assets. None is an explicit value, never a registered fake transcription method. Decode existing files compatibly:

- A valid new field is authoritative. Only when it is absent, map legacy `ndm.transcription.apple` to Apple Local, legacy `ndm.transcription.cohere` to Q4, and an absent/null legacy value to None. A genuinely missing Settings file also yields None.
- Unknown tokens/methods, malformed records, and protected-data/read failures are unavailable outcomes, not fresh settings or permission to infer. Preserve the record, show a sanitized recovery reason, and do not fall back to the legacy field when a present new field is invalid. A later explicit choice may replace a decodable unknown selection; unreadable/corrupt records retain Task 1's fail-closed write behavior.
- Migration is a decode mapping, not a write on screen entry. On an explicit mutation, reread and merge the bounded current record, persist atomically with existing protection, then publish the saved selection and notify the queue. Retire the legacy field only in that successful write. Preserve onboarding and the destination; a failed read/write leaves committed UI/queue state unchanged. Subsequent onboarding/destination writes must preserve the new choice too.

Use a selection generation that changes on each successful choice change, including away-and-back changes, and is invalidated across lifecycle/reload boundaries. This is distinct from the provider's effective-settings schema revision. A cached ready Boolean or UI checkmark never grants inference authority.

### Queue snapshot and provenance contracts

Resolve one immutable snapshot of selection token/generation, provider method, language, effective-settings revision, descriptor/installation identity, runtime, conversion, and chunking policy. Extend the existing settings/preflight port as needed so preflight receives that snapshot, rather than consulting mutable selection after an await. Immediately before durable claim, recheck selection generation, app activation, job/revisions, exact approved descriptor/installed identity, oldest-ready eligibility, and worker availability. A stale preflight is discarded and reconsidered; never merge its installed identity with another variant's current settings.

After claim, the attempt and its audio/model leases retain that exact variant through conversion, inference, candidate publication, and settlement. Later selection changes affect only new attempts; they do not relabel, restart, or automatically cancel active inference. None/unavailable choices keep unclaimed audio pending using existing actionable recovery, without changing microphone/folder/storage capture gates. Selection/readiness changes may wake eligible waiting jobs; failed jobs require manual retry, restored jobs require Resume, and verified candidates/drafts awaiting save continue without transcription. Preserve one worker, oldest-ready scheduling, the ten-minute cutoff, audio retention, and no advancement until the adapter relinquishes resources.

For new Cohere attempts, use effective `settingsRevision` **2** to identify this expanded variant contract; Apple remains at revision 1. Keep closed schemas for supported revisions rather than widening validation to arbitrary strings or extra fields. A candidate's selection/quantization, model/installed identity, revision, runtime, conversion/chunking, and language must all match one bundled trusted descriptor independently of whichever model is currently selected or installed.

Keep Diary Snippet `schema_version: 1` and the approved flat keys. Emit `transcription_settings_revision: 2`, `transcription_method_id: ndm.transcription.cohere`, the base `transcription_model_id`, and `transcription_model_version` as `<immutable repository revision>:<quantization>` for new revision-2 attempts, distinguishing Q4/Q5 even from one repository revision. Derive all fields from the validated attempt, not current Settings. Runtime/conversion fields retain their meanings; `language` and `transcription_language_hint` retain the original `en-US`/`ko-KR` hint. No new method ID or front-matter key is needed.

Retain explicit validation support for verified legacy Cohere revision-1/Q4 candidates and drafts with their historical pins and original version encoding; retain Apple revision-1 support. Upgrade or selecting Q5/None must not invalidate, reinterpret, or retranscribe them. Existing saved Markdown is not rewritten by this migration. Cover candidate → draft → Markdown → decode, including reopening an old candidate with Q5 selected and no Q4 model installed.

Serialize explicit Cohere installations across variants, with other install actions showing the busy reason until the current operation settles. Late progress/completion/cancel callbacks update only that operation. Preflight capacity against current free space and the existing M12 peak-allocation formula/reserve, accounting for retained copies without double-counting already allocated bytes. Unknown/insufficient capacity prevents a download. Preserve exact byte ceilings, allowed redirects, bounded hash/GGUF verification, atomic publication/reopen, file protection/backup exclusion, lease-aware replacement, and abandoned-staging reconciliation.

Apply the existing explicit `en`/`ko`, actual Metal with no automatic CPU fallback, nontruncated output, silence-aware chunks no longer than 45 seconds, complete seam assembly, and cancellation/settlement contracts to both variants. A visible Q5 row is not evidence that these checks passed.

2. Reproduce each boundary separately. 5. The deterministic regression suspends a catalog page, requests an explicit replacement traversal, and then delivers a callback from the removed presenter.
