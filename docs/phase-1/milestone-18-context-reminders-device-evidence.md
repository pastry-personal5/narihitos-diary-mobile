Status: Draft

Stage M18a covers D06–D08; stage M18b covers D01–D05, D09 (context parts) and D10. Record target-iPhone evidence for recording-start context, permission/privacy boundaries, and pending-work reminders after implementation. Use disposable synthetic recordings and controlled context/clock fixtures; no scenario has been run for this plan.

## Run record

For each scenario, record device/iOS/app revision, permission/preference/accuracy classes, service/provisioning availability, recording lifecycle boundary, accepted/omitted group classes, pending owner/state class, calendar/timezone/DST fixture, computed-versus-observed trigger class, relevant fault boundary, result, and evidence method. Separate actual system behavior from injected adapter/fake-clock checks; a shortened debug reminder does not prove the production next-day calculation. Mark partial, blocked, failed, and passed observations distinctly.

Do not commit audio, diary/title/place/weather text, exact coordinates or sample/recording timestamps tied to a person, account/team/provider identifiers, folder names/paths, bookmarks, raw SDK errors, or sensitive screenshots/network logs. Use sanitized reason codes, age/accuracy boundary classes, relative durations, offsets, and opaque local references. Document which observations require an actual location change, system authorization/provisioning, lock, or notification delivery; simulator results cannot close those requirements.
