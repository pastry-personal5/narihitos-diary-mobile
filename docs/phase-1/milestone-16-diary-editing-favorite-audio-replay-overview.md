# P1-M16: Diary editing, Favorite, and audio replay overview

Status: Planned

Add body-only editing, a separate Favorite toggle, and safe audio replay to Diary Snippet detail. Preserve submitted changes through interrupted iCloud writes, reject stale versions, and keep legacy assets read-only.

## Entry and locked inputs

- Implementation follows P1-M15 under [Phase 1 order](phase-1.md), unless the owner authorizes a reorder. M15 is active; this planning request does not start M16 implementation or close earlier validation/device evidence.
- Use the approved [product behavior](../product-behavior.md#assets-and-metadata), [GUI](../ux-gui.md#planned-owner-approved-behavior), [schema/title/interface contracts](milestone-05-decisions-architecture.md), and [edit/conflict architecture](../architecture.md#asset-commit-and-icloud-behavior). No new product decision, schema, dependency, build tool, or transcription method is required.
- Consume M15's [exact-version detail and catalog handoff](milestone-15-main-collection-diary-detail-architecture.md), M7's bounded codec, M8's destination validation, M13's title policy, and M14's [verified pair, upload, and conflict mechanics](milestone-14-icloud-commit-reconciliation-architecture.md). A catalog handle or `audioAvailable` flag alone grants neither write access nor playback access.
- M17 retains full Pending/Failed/Incomplete/Conflict recovery screens, ambiguous-version choice, and confirmed removal. M18 retains context acquisition and reminders. M19 retains complete-experience validation. M16 must provide durable typed edit-recovery records for M17 rather than lose edits until those screens exist.

## Implementation prerequisites

- **Committed-asset transactions:** M14's `DiaryPairStorePort`, conflict inspection, and coordinator currently accept a `QueueJob` and capture-time destination. A finished asset may have no remaining capture workspace. Add a type-specific edit transaction and destination capability; do not manufacture a recording job, depend on deleted staging, or treat an asset ID/path as ownership.
- **Version authority:** exchange M15's session/resource/version handle for a freshly validated edit or replay capability. Recheck both files, destination/account identity, supported schema, duplicate claims, and unresolved provider versions at use. Distinct resources sharing an ID remain separate and blocked from mutation.
- **Text-only conflicts:** two Markdown versions may refer to the same uniquely validated audio version. Preserve each complete pair; do not rewrite audio to create a newer timestamp. Equal audio times remain ambiguous under the existing whole-pair rule. A local unpublished edit has no iCloud modification time and cannot win automatically by `updated_at` or device time.
- **Audio-session ownership:** `AppleCaptureEnvironment` currently configures/deactivates `AVAudioSession` directly. Introduce shared session ownership for recording and replay, with separate coordinators, so replay teardown cannot deactivate an ongoing capture. This is a targeted adapter change with M9 regression coverage.
- **Legacy replay:** implement it only for the fixture-backed legacy grammar/pairing established by M15. Unconfirmed or ambiguous legacy content stays preserved in recovery; M16 does not invent a decoder or migrate old files.

## Scope

| Work | Required behavior |
|---|---|
| Body editor | Open `Edit Diary` from supported v1 detail. Edit only the managed body; Title and recording metadata have no edit fields. Save validates the UTF-8 body limit, durably retains the submitted revision, regenerates the title, and writes with the editor's expected pair version. Keep the buffer on failure and protect unsaved changes when leaving. Empty text saves as `Untitled`. |
| Title and metadata | Reuse the bounded whole-body AI-or-fallback title policy in the body's current language. Persist title and provenance together, with at most 30 Swift grapheme clusters including ellipsis. Preserve recording language/hint, identity, UTC names, `created_at`, audio, transcription provenance, optional groups, and unknown scalar values. A saved edit updates `updated_at`; sync alone does not. |
| Favorite | A separate on/off control beside Title submits the desired Boolean against an exact version. It updates `favorite` and `updated_at`, preserves body/title/title provenance, and never invokes title generation. Duplicate callbacks/retries cannot toggle twice. |
| Edit durability | Keep a protected, backup-excluded transaction candidate and its verified audio binding until the edited pair validates and both exact file versions report upload success. Retry submitted work when access returns, without retranscription, new asset IDs, or blind overwrite. Reconcile crashes and external changes before further publication or cleanup. |
| Replay | In bottom Metadata, provide play/pause, seeking, and elapsed/total media time for a freshly verified v1 or eligible read-only legacy pair. Obtain a bounded private audio lease; handle provider waits, interruptions, route loss, teardown, and capture priority without changing source files. |
| Catalog and recovery | Refresh M15 from observed committed versions. Fence old UI/title/player callbacks; preserve submitted edits independently of disposable catalog state. Return typed waiting, changed/conflict, incomplete/unsupported, storage, and settlement outcomes with existing All recovery routes. |
| Interface | Keep Title/Favorite, inert body, then Metadata order. Supply approved custom template Favorite/play/pause/seek artwork and canonical accessibility semantics, keyboard-safe editing, 44-point targets, Dynamic Type, light/dark, Reduce Motion, and the nonforeground privacy cover. |

## Out of scope

No title or metadata editor, transcript sidecar, edit history, automatic merge, legacy rewrite/migration, finished-asset deletion, word-linked replay/highlighting, playback speed, background playback feature, remote media, new reminder policy, or change to conflict ordering. Recovery actions assigned to M17 are not implemented by this plan. Replay does not authorize access to arbitrary pending audio or another folder.

## Completion checklist

- [ ] Type-specific edit/replay ports exchange opaque capabilities and typed results. Fresh full-pair validation rejects legacy mutation, unsupported/malformed/incomplete content, duplicate-ID ambiguity, stale handles, unsafe references, and unresolved provider versions. No URL, bookmark, platform player, or provider error enters Domain/Application.
- [ ] `Edit Diary` changes only the body, preserves failed/unsaved input, protects leaving with unsaved changes, and enforces the 1 MiB UTF-8 body boundary without silent truncation or broken English/Korean text composition. Empty and whitespace-only bodies use the approved empty-body title policy. Submitted revisions survive process termination once acceptance is reported.
- [ ] Every body save reuses the approved whole-body language/title budgets, fallback, Unicode limit, and provenance rules. Late title results cannot affect a newer body, Favorite transaction, changed destination, or closed editor. Readiness changes alone never rewrite a saved fallback title.
- [ ] Saved body/Favorite changes preserve all immutable recording values and audio bytes, unknown scalar values, and malformed optional-group values. `updated_at` belongs to the saved revision and is stable across retries; sync/read/replay do not change it. Favorite is a desired-state operation, changes no body/title/provenance, and serializes with body saves for the same resource.
- [ ] A versioned protected, backup-excluded edit journal persists source-pair/destination/installation binding, candidate and audio evidence, publication checkpoints, upload proof, and cleanup state. Storage/protected-data failures report no false acceptance. Reopen after each checkpoint converges without duplicate assets, repeated overwrite, early candidate loss, or a retained original-transcript document.
- [ ] Coordinated Markdown replacement checks both expected source versions at the operation, preserves external audio, verifies the resulting pair, and retains staging until separate exact-version upload reports and a final unchanged check. Crashes after replacement but before checkpoint are reconciled from positive write evidence; matching IDs or candidate bytes alone never establish ownership.
- [ ] Folder/account changes and provider stalls fence new work and stale callbacks. An accepted transaction remains bound to its original resource/folder and cannot be redirected into a new active folder. Unsettled accessors retain ownership without accumulating retries; unrelated recording/queue/catalog work continues. Restored submitted edits require installation-bound review before publication.
- [ ] External edits before/during save preserve the user's candidate and current external pair with typed recovery. Shared unchanged audio is validated for each snapshot; equal/missing/cross-ordered times stay ambiguous. No unpublished candidate wins by device time, no pair is guessed or merged, and no source/version is removed before M14 proof and any M17 confirmation.
- [ ] A fresh replay lease validates exact resource versions, safe containment, size, format, clean decoder EOF, and decoded duration. Limits remain 64 MiB/301 seconds for v1 and 64 MiB/60 minutes for eligible legacy audio. Source replacement, unsupported input, failed decoding, cancellation, and private-cache cleanup cannot expose another file or modify the source.
- [ ] Replay supports play/pause, bounded seeking, elapsed/total time, end-of-audio, interruption/route-loss handling, and foreground/detail teardown. Recording has session priority; replay cannot change/deactivate capture, resume unexpectedly after capture, or use the microphone. M9 lock/background capture behavior remains intact.
- [ ] Favorite/playback custom bitmaps, `Favorite` state, `Play audio`, `Pause audio`, and adjustable `Audio position` with `{elapsed} of {total}` and 15-second steps meet the approved interface. Keyboard/focus, English/Korean composition, small/large iPhones, landscape, largest Dynamic Type, VoiceOver, Reduce Motion, inert text, and privacy-cover behavior pass checks.
- [ ] Focused tests cover title/version races, field preservation, desired-state retries, write/checkpoint/upload/cleanup faults, restored edits, shared-audio conflicts, provider/cancellation settlement, source swaps, replay seek/teardown, and capture-session arbitration. The [M16-D01–D09 target-iPhone record](milestone-16-diary-editing-favorite-audio-replay-device-evidence.md) contains redacted pass evidence; missing evidence remains unchecked.
- [ ] Affected README, architecture, UX, milestone, and index docs describe implemented behavior. The delegated runner reports `make lint` and `TEST_DESTINATION=… scripts/validate.sh` passing with the destination recorded; an unavailable required command leaves this item unchecked with its blocker.

The checklist is for implementation completion. This documentation-only planning change supplies no runtime, simulator, or physical-device acceptance evidence.
