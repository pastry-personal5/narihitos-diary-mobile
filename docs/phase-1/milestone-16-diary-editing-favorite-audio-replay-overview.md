## Integration contracts

- **Committed-asset transactions:** M14's creation store/coordinator accept a `QueueJob` and capture-time destination. A finished asset may have no remaining capture workspace. M16 uses an independent `DiaryEditStorePort` transaction and committed-destination capability; never manufacture a recording job, depend on deleted staging, or treat an asset ID/path as ownership.
- **Version authority:** exchange M15's session/resource/version handle for a freshly validated edit or replay capability. Recheck both files, destination/account identity, supported schema, duplicate claims, and unresolved provider versions at use. Distinct resources sharing an ID remain separate and blocked from mutation.
- **Restart identity:** M15's catalog session/resource/version UUIDs are disposable browse capabilities, not stable provider identities and must never be serialized into an edit journal. At acceptance, resolve the handle inside the adapter to a destination-bound resource key plus observed Markdown/audio versions and content evidence that can be revalidated after launch. Failure to establish that binding blocks acceptance without losing the editor buffer.
- **Text-only conflicts:** two Markdown versions may refer to the same uniquely validated audio version. Preserve each complete pair; do not rewrite audio to create a newer timestamp. Equal audio times remain ambiguous under the existing whole-pair rule. A local unpublished edit has no iCloud modification time and cannot win automatically by `updated_at` or device time.
- **Audio-session ownership:** capture and replay now share `AudioSessionOwnership`, with separate coordinators and a platform configuration port. Only the current owner may deactivate the session. This targeted adapter change requires M9 regression coverage and physical capture checks.
- **Shared title ownership:** composition now injects one `DiaryTitlePolicy` into draft adoption and edits. Preserve its shared model-ownership guard; a second instance would permit overlapping model calls. A deadline/fallback result does not prove that cancelled title work has settled.
- **M20 maintenance compatibility:** integrate edit acceptance, title/publication/cleanup owners, and replay acquisition/player leases with the implemented [Danger Zone admission and restart barrier](milestone-20-enhancements-fixes-refactoring-architecture.md#task-9-danger-zone-purge-actions-in-settings). Place edit recovery and replay artifacts inside the existing private-staging scope; an accepted edit must block active-folder purge until completed or separately purged. Do not defer this integration to M21.
- **Legacy replay:** implement it only for the fixture-backed legacy grammar/pairing established by M15. Unconfirmed or ambiguous legacy content stays preserved in recovery; M16 does not invent a decoder or migrate old files.

## Scope

| Work | Required behavior |
|---|---|
| Body editor | Open `Edit Diary` from supported v1 detail. Edit only the managed body; Title and recording metadata have no edit fields. Save validates the UTF-8 body limit, durably retains the submitted revision, regenerates the title, and writes with the editor's expected pair version. Keep the buffer on failure and protect unsaved changes when leaving. Empty text saves as `Untitled`. |
| Title and metadata | Reuse the bounded whole-body AI-or-fallback title policy in the body's current language. Persist title and provenance together, with at most 30 Swift grapheme clusters including ellipsis. Preserve recording language/hint, identity, UTC names, `created_at`, audio, transcription provenance, optional groups, and unknown scalar values. A saved edit updates `updated_at`; sync alone does not. |
| Favorite | A separate on/off control beside Title submits the desired Boolean against an exact version. It updates `favorite` and `updated_at`, preserves body/title/title provenance, and never invokes title generation. Duplicate callbacks/retries cannot toggle twice. |
| Edit durability | Keep a protected, backup-excluded transaction candidate and its verified audio binding until the edited pair validates and both exact file versions report upload success, or an explicitly confirmed internal-staging purge removes them. Retry submitted work when access returns, without retranscription, new asset IDs, or blind overwrite. Reconcile crashes and external changes before further publication or cleanup. |
| Replay | In bottom Metadata, provide play/pause, seeking, and elapsed/total media time for a freshly verified v1 or eligible read-only legacy pair. Obtain a bounded private audio lease; handle provider waits, interruptions, route loss, teardown, and capture priority without changing source files. |
| Catalog and recovery | Refresh M15 from observed committed versions. Fence old UI/title/player callbacks; preserve submitted edits independently of disposable catalog state. Return typed waiting, changed/conflict, incomplete/unsupported, storage, and settlement outcomes with existing All recovery routes. |
| Interface | Keep Title/Favorite, inert body, then Metadata order. Supply approved custom template Favorite/play/pause/seek artwork and canonical accessibility semantics, keyboard-safe editing, 44-point targets, Dynamic Type, light/dark, Reduce Motion, and the nonforeground privacy cover. |
