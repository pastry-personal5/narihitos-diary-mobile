# P1-M11: Apple on-device transcription overview

Status: Done (owner decision; by-human test and evidence pending)

Add a production Apple `SpeechTranscriber` method for English and Korean recordings, including truthful system-model readiness and installation controls, local-only file transcription, durable result handoff, and adapter-specific cancellation evidence. This milestone stops at a protected transcription-result candidate; P1-M13 turns that candidate into the one managed Diary body.

## Entry condition

- Follow [Phase 1 order](phase-1.md): implementation starts after P1-M10 is Done or the owner explicitly authorizes a reorder. Planning M11 does not close the open M8–M10 physical-device evidence.
- Use the approved [transcription behavior](../product-behavior.md#transcription), [queue lifecycle](milestone-10-durable-processing-queue-architecture.md), [P1-M5 recording, queue, and privacy contract](milestone-05-decisions-architecture.md#recording-queue-and-privacy-contract), and [network/local-inference boundary](../architecture.md#network-and-local-inference). M9 supplies verified mono AAC audio and M10 supplies foreground ordering, attempt generations, timeout, retry, removal, and method registration.
- Use the iOS 27 `SpeechAnalyzer`, `SpeechTranscriber`, and `AssetInventory` APIs in the installed Xcode SDK. Do not use `SFSpeechRecognizer`, `DictationTranscriber`, a server-recognition fallback, or a new dependency.
- Ask the owner before changing dependencies or build tools, weakening local-only inference, silently releasing a language reservation, or changing an approved queue outcome.

## Scope

- Register stable method `ndm.transcription.apple` for `en-US` and `ko-KR`. Resolve each user hint through `SpeechTranscriber.supportedLocale(equivalentTo:)`; never replace it with `Locale.current`, language detection, or an implicit alternate locale.
- Refine the M10 method contract for asynchronous, generation-fenced readiness and installation state. Distinguish unavailable hardware, unsupported locale, downloadable, downloading with bounded progress, installed/ready, transient failure, and reservation-capacity failure. Refresh at Settings entry, app activation, immediately before claim, and after an installation attempt settles; do not persist a stale ready Boolean.
- Add an Apple Transcription Settings section that shows English and Korean readiness independently, offers Download Model only when appropriate, shows sanitized failure state, and exposes explicit method selection. Recovery selection offers methods ready for the recording’s language; readiness is checked again at claim. With no previous selection, jobs wait for a user choice; selecting Apple persists the stable method ID and is reused without implying that both language assets are ready. M12 later adds the Cohere choice without changing this contract.
- Install only system-managed assets associated with a configured `SpeechTranscriber`. Reserve the resolved locale, obtain an `AssetInstallationRequest`, show its progress, await `downloadAndInstall()`, and re-read actual status. Do not interpret `downloading` as ready, fabricate a byte size the API does not expose, or automatically release another reservation. If the target phone cannot reserve both approved locales, leave the evidence open and ask the owner before adding an eviction policy.
- Give the Apple adapter verified read-only access to the fixed M9 audio through an adapter-private source, not a persisted path in Domain/Application. Recheck ownership, regular-file containment, size, duration, mono AAC metadata, and protected-data availability before opening the file. Treat inaccessible protected data as waiting and malformed, substituted, incompatible, or decoder-failing audio as an entry-level failure with the original audio retained.
- Transcribe the prerecorded file with `SpeechAnalyzer` and `SpeechTranscriber` using the installed SDK's nonvolatile transcription preset. Consume finalized results only, finalize through the last input sample, and do not accept success until the input task, result sequence, and analyzer all settle. Preserve Unicode text, join final segments deterministically without duplicating volatile results, enforce the 1 MiB Diary-body bound, and reject output with no usable alphanumeric text as `No usable diary text was found.`
- Persist a bounded, versioned, backup-excluded transcription-result candidate atomically before moving a job to `resultReady`. Bind it to job ID, attempt generation/ID, recording language hint, selected method, resolved Apple locale, settings revision, conversion/runtime provenance, and source-audio identity. A verified published candidate survives reconciliation; a crash before durable publication can require a manual retry with audio retained and must never fabricate success. P1-M13 adopts the candidate bytes as the initial managed body and removes this intermediate; it never becomes a permanent separate original transcript.
- Snapshot effective provenance before inference. Record settings revision `1`, requested and resolved BCP-47 locales, the transcription preset, nonvolatile result policy, and the versioned file-input/conversion path. Record Apple SpeechAnalyzer runtime and OS version; omit model ID/version when Apple exposes neither rather than inventing them.
- Implement adapter cancellation as an acknowledged teardown: invalidate the queue generation, cancel input/results tasks, call `cancelAndFinishNow()`, release the audio handle, and signal relinquishment only after all underlying work has stopped. The M10 worker stays occupied until that acknowledgment, including after its ten-minute timeout or confirmed removal. Late results cannot stage text or change a newer attempt.
- Add a truthful local-only boundary. Model installation may contact Apple for system assets, but installed-model inference must complete in airplane mode and must not send app audio or result text to a remote inference endpoint. Diagnostics contain only typed state, duration, counts, and opaque IDs—never audio, transcript, locale-reservation internals, file paths, or raw platform errors.
- Add focused fakes, adapter tests, queue integration tests, Settings/accessibility tests, and the target-iPhone evidence matrix in the [M11 device evidence record](milestone-11-apple-on-device-transcription-device-evidence.md).

## Out of scope

- Cohere artifact installation, manifest verification, runtime integration, chunking, and Metal cancellation remain P1-M12.
- Diary body/draft creation, title generation, title provenance, and removal of the adopted intermediate remain P1-M13. M11 creates no Markdown, title, favorite value, or finished Diary Snippet.
- iCloud publication, upload proof, destination replacement, incomplete-pair repair, and conflict handling remain P1-M14/P1-M17. Destination availability does not gate local Apple transcription.
- Full Pending/Failed interfaces and Choose Method recovery routing remain P1-M17; M11 provides the typed actions and truthful Settings/minimal queue presentation needed to exercise the method.
- Main collection/notices, playback, optional context, reminders, and complete-experience adversarial validation remain P1-M15–P1-M19.
- Live transcription during capture, word timing/highlighting, volatile partial text, automatic locale detection, custom vocabulary, `DictationTranscriber`, and speech-server fallback are not introduced.

## Acceptance evidence

Implementation has started with a bounded final-segment text collector, a generation-fenced Apple readiness probe, explicit method-selection persistence, and a protected candidate-store boundary. The queue requires a verified candidate before advancing to `resultReady` and checks candidates during recovery. The Apple adapter and per-language status are connected, but inference teardown, queue races, protected storage, and platform behavior still need the remaining planned tests and review. The owner approved progress-only Apple installation. The public API does not document a pre-download byte count or required-space estimate, so neither is displayed. The [device record](milestone-11-apple-on-device-transcription-device-evidence.md) does not yet contain physical-device results.

Focused text-collector, readiness, installer, queue, candidate-store, source-audio, settings, and analyzer-lifecycle tests passed on an iPhone 18 Pro simulator. Controlled-session tests cover finalization, oversized and unusable results, input and result-stream failures, confirmed removal, timeout, and delayed teardown. An iOS 27.1 simulator UI inspection showed separately labeled English and Korean unavailable states and the explicit unselected method control; the simulator does not establish real-device readiness. Candidate-store tests inject a protection policy because the simulator returns no file-protection attribute; the real protection check remains a physical-device evidence item. Source inspection and `AppleTranscriptionAdapterTests` cover the registered descriptor and platform boundaries. On 2026-11-02, `make lint` and the generated simulator app build passed. The full `scripts/validate.sh` test step ran but failed in four unfinished P1-M12 Cohere tests (`CohereAudioProcessingTests`, `CohereModelManagerTests`, and `TranscriptionCandidateStoreTests`); no Apple test appeared in the failure list. The full gate remains unchecked, and the physical-device matrix remains outstanding. After the progress-only change, the focused Apple installation, readiness presentation, speech attempt, transcription adapter, and readiness suites passed on the iPhone 18 Pro simulator. Review corrected stale download-unavailable copy, added a typed reservation-capacity message, and prevented install settlement from refreshing readiness while the app is inactive. Physical Apple asset installation and inference still require the target-iPhone scenarios.

Check an item only with focused automated tests, source/configuration inspection, a successful repository gate, or a redacted physical-device observation. Simulator fakes can prove state transitions, bounds, persistence, and cancellation fencing; they cannot prove real Apple locale support, system-asset installation, AAC model compatibility, offline inference, actual teardown latency, or the absence of inference network traffic on the target phone.

Use synthetic English/Korean fixtures and record only locale category, duration class, typed outcome, elapsed/resource measurements, and whether expected sentinel phrases were present. Do not record audio, transcript text, paths, raw logs, Apple account data, or reservation identifiers in Git.
