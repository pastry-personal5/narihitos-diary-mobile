# P1-M1: Open product and architecture decisions

Status: Active

This inventory lists decisions still open after the 2026-11-01 owner interview and the on-device Cohere v1 scope change. Confirmed behavior is in [product behavior](../product-behavior.md), [planned GUI behavior](../ux-gui.md), and the [Phase 1 changelog](../phase-1/changelog.md); the owner's [initial ideas](initial-ideas-from-owner.md) remain proposals where they were not confirmed. ## Platform feasibility notes

- **Apple speech:** [SpeechTranscriber](https://developer.apple.com/documentation/speech/speechtranscriber) exposes device availability and supported versus installed locales; [AssetInventory](https://developer.apple.com/documentation/speech/assetinventory) manages model download and installation. The requested offline path therefore needs an on-device readiness check for both en-US and ko-KR before it is offered. Published API availability does not establish recognition quality on the target phone; compare it with Cohere on the same recordings.
- **Recording and replay:** [AVAudioApplication](https://developer.apple.com/documentation/avfaudio/avaudioapplication/requestrecordpermission%28completionhandler%3A%29) requires microphone permission and an `NSMicrophoneUsageDescription` purpose string. [Audio-session interruption notifications](https://developer.apple.com/documentation/avfaudio/handling-audio-interruptions) cover calls and other interruptions; playable partial clips queue automatically, while unplayable clips stay in Failed Recordings with a reason. [AVAudioPlayer](https://developer.apple.com/documentation/avfaudio/avaudioplayer) supplies play, duration, and playback position for the approved replay controls.
- **Queue and reminders:** Apple's [background-task guidance](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app) leaves launch timing to the system, so the approved foreground-only queue must persist state and resume on app open. [Notification authorization](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications) can be changed later, and [local notification delivery](https://developer.apple.com/Documentation/usernotifications/) is not guaranteed. Pending state in the app remains necessary even when a reminder is scheduled.
- **Folders and conflicts:** The [directory picker](https://developer.apple.com/documentation/uikit/providing-access-to-directories) can return local, iCloud, or third-party folders and provides a security-scoped URL that can be bookmarked. Access can later be revoked or fail; iCloud-only selection and creation of a new folder need a device prototype. Apple's [iCloud document sample](https://developer.apple.com/documentation/uikit/synchronizing-documents-in-the-icloud-environment) uses coordinated I/O and detects version conflicts. Its modification-date example does not settle the owner's cross-device “latest edit” rule for this app.
- **Optional context and interface:** [Core Location](https://developer.apple.com/documentation/corelocation/requesting-authorization-to-use-location-services) prefers permission requests when location is needed. [WeatherKit](https://developer.apple.com/weatherkit/) requires entitlement and attribution, and publishes a monthly call allowance; acquisition and display need separate failure handling. Apple's [appearance guidance](https://developer.apple.com/design/human-interface-guidelines/dark-mode) calls for icons that work in both appearances, and [SwiftUI accessibility modifiers](https://developer.apple.com/documentation/swiftui/view-accessibility) can label custom controls. These APIs support the planned UI without deciding its remaining layout or copy.
