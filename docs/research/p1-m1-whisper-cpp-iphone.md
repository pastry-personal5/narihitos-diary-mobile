# P1-M1: whisper.cpp on iPhone 17 Pro Max

Status: Active

This research assesses local transcription with whisper.cpp for v1's five-minute en-US and ko-KR diary recordings. It identifies models worth measuring on the target phone; it does not approve a dependency, add a transcription method, or change the confirmed v1 behavior. Sources were checked on 2026-11-01.

## Runtime and target-phone feasibility

The [whisper.cpp project](https://github.com/ggml-org/whisper.cpp) supports iOS, C/C++ integration, Metal, optional Core ML encoder acceleration, and quantized weights. Its [SwiftUI example](https://github.com/ggml-org/whisper.cpp/blob/master/examples/whisper.swiftui/README.md) builds an XCFramework and shows that a Core ML encoder requires both its `.mlmodelc` and the GGML model, because the decoder still uses GGML. The [XCFramework build script](https://github.com/ggml-org/whisper.cpp/blob/master/build-xcframework.sh) enables Metal and has an iOS device target; embedding it in this SwiftUI/XcodeGen app would be an implementation and dependency decision for a later milestone.

Apple lists an [A19 Pro, six-core GPU, and 16-core Neural Engine](https://support.apple.com/en-us/125091) for iPhone 17 Pro Max. These specifications do not establish app memory headroom or transcription speed. The whisper.cpp [memory table](https://github.com/ggml-org/whisper.cpp#memory-usage) reports about 3.9 GB for an unquantized large model, but does not give an iPhone 17 Pro Max peak-memory figure for the quantized candidates below. Model file size must not be used as a RAM estimate.

A developer [reported](https://buildcomcarlos.com/en/articles/whisper-iphone-coreml-erro-14-metal.html) running `large-v3-turbo-q5_0` through whisper.cpp/Metal on one iPhone 17 Pro Max: a 16.8-second **Portuguese** sentence took 1.147 seconds after loading; `medium-q5_0` took 1.9 seconds for a different 14-second sentence. They reported about 6.2 seconds for first-run Metal shader compilation. This is useful evidence that the path can run on the named phone, but it is one developer's short-clip measurement, with no English/Korean accuracy, five-minute latency, peak memory, battery, or thermal results. A separate [upstream issue](https://github.com/ggml-org/whisper.cpp/issues/3648) reports an immediate iPhone 17 Pro Max crash without a reproduction or diagnosis. Run a device prototype before relying on either report. [Argmax's iPhone 17 benchmarks](https://www.argmaxinc.com/blog/iphone-17-on-device-inference-benchmarks) use a different Core ML/Neural Engine implementation and must not be presented as whisper.cpp performance.

The existing recording candidate is [mono AAC-LC in `.m4a` at 44.1 kHz](p1-m1-audio-format.md#provisional-recommendation-and-validation). whisper.cpp's [C API expects 16 kHz floating-point PCM samples](https://github.com/ggml-org/whisper.cpp/blob/master/include/whisper.h); its CLI example accepts 16-bit WAV and demonstrates a 16 kHz mono conversion. An iOS integration would decode `.m4a`, downmix and resample with Apple's [AVAudioConverter](https://developer.apple.com/documentation/technotes/tn3136-avaudioconverter-performing-sample-rate-conversions), and pass the resulting PCM to the runtime. The archived `.m4a` can remain unchanged. Five minutes of mono 16 kHz float PCM is about 19.2 MB before buffers and model allocations (300 × 16,000 × 4 bytes). Whisper [processes audio in 30-second windows](https://github.com/openai/whisper#python-usage); a five-minute recording therefore needs long-form handling and a real end-to-end measurement.

## Local model candidates

“State of the art” below refers to published model-family or dataset results, not proven accuracy in this app. [OpenAI's model list](https://github.com/openai/whisper#available-models-and-languages) identifies `large-v3` and the faster `large-v3-turbo` as current multilingual Whisper checkpoints; `.en` weights cannot serve ko-KR. The [whisper.cpp model repository](https://huggingface.co/ggerganov/whisper.cpp) publishes ready-to-load GGML variants. Sizes are **download sizes**, not peak RAM; quantization can alter accuracy and runtime and needs its own test.

| Candidate GGML file | Languages and disk size | Evidence and role in a device comparison |
|---|---|---|
| [`ggml-large-v3-turbo-q5_0.bin`](https://huggingface.co/ggerganov/whisper.cpp/blob/main/ggml-large-v3-turbo-q5_0.bin) | English + Korean; **547 MiB** | Best first shared-language trial: upstream GGML artifact and the short iPhone/Metal report above. OpenAI calls Turbo faster than full v3 with some accuracy loss; Korean diary accuracy is unmeasured. |
| [`ggml-large-v3-turbo-q8_0.bin`](https://huggingface.co/ggerganov/whisper.cpp/blob/main/ggml-large-v3-turbo-q8_0.bin) | English + Korean; **834 MiB** | Same checkpoint at a less aggressive quantization. Compare with q5 only if q5 quality needs improvement; no target-phone quality or speed result found. |
| [`ggml-large-v3-q5_0.bin`](https://huggingface.co/ggerganov/whisper.cpp/blob/main/ggml-large-v3-q5_0.bin) | English + Korean; **1.1 GiB** | Full-model quality comparator. [OpenAI](https://huggingface.co/openai/whisper-large-v3) reports broad improvement over v2, but this q5 artifact's accuracy and five-minute device latency are unmeasured. |
| [`ggml-small-q5_1.bin`](https://huggingface.co/ggerganov/whisper.cpp/blob/main/ggml-small-q5_1.bin) | English + Korean; **181 MiB** | Smaller storage/memory fallback to measure, not a quality recommendation. |
| [`ggml-buzzasr-korean-q5_0.bin`](https://huggingface.co/wavu/buzzasr-korean-ggml) | **Korean only**; **1.08 GB** | Exploratory Korean quality candidate. Its [source fine-tune](https://huggingface.co/BuzzASR/korean) reports 4.61% normalized CER on combined FLEURS/Common Voice 25 versus 5.72% for zero-shot Whisper large-v3. The third-party GGML card shows CrispASR usage, so verify loading in upstream whisper.cpp; the reported score does not validate q5, mixed-language speech, or diary clips. |
| [`distil-large-v3.5-ggml`](https://huggingface.co/distil-whisper/distil-large-v3.5-ggml) | **English only**; **1.52 GB** | Official GGML conversion for whisper.cpp. The [model card](https://huggingface.co/distil-whisper/distil-large-v3.5) reports 7.08% short-form out-of-domain WER versus 7.30% for Turbo in its evaluation, but worse long-form WER; this is not a matched iPhone or Korean result. A separate Korean model would also be needed. |

OpenAI's [Whisper weights and code](https://github.com/openai/whisper#license) and the [whisper.cpp runtime](https://github.com/ggml-org/whisper.cpp/blob/master/LICENSE) are MIT licensed. The cited GGML repository labels its OpenAI conversions MIT; the BuzzASR and Distil-Whisper model cards also label those specific artifacts MIT. These permissive licenses appear compatible with this project's Apache-2.0 code policy, subject to checking the exact artifact and retaining required notices before distribution. Local inference has no per-minute API fee and does not need to upload speech, but model distribution, storage, CPU/GPU time, and battery still have costs.

The whisper.cpp repository now also ships a [Parakeet CLI and GGML weights](https://huggingface.co/ggml-org/parakeet-GGUF), but NVIDIA's [Parakeet TDT 0.6B v3](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3) supports English and 24 other European languages, **not Korean**. It is a separate runtime path from `whisper-cli`, so it is not a one-model answer for this app. Qwen3-ASR and Apple's SpeechTranscriber are likewise outside the Whisper-weight candidates in this table.

## What the next device evaluation must settle

1. On a physical iPhone 17 Pro Max with the intended iOS build, load pinned runtime/model revisions and test cold start, warm start, Metal-only operation, peak app memory, failures, battery/thermal behavior, and a full five-minute recording. The simulator cannot establish these properties. Record the encoded file and decoded PCM sizes and verify `.m4a` to 16 kHz mono conversion.
2. Compare at least Turbo q5, full v3 q5, and the smaller fallback on the **same** consented en-US and ko-KR diary-like recordings, including five-minute clips, pauses/silence, names, dates, numbers, noise, accents, and code switching. Measure English WER, Korean CER, omissions, hallucinations, latency, and replay-independent audio quality with one stated normalization policy. Compare against the existing Apple and Qwen options under their own approved conditions; published scores across unrelated datasets are not a head-to-head result.
3. Force transcription rather than translation and pass the user's `en`/`ko` hint where supported; preserve the original transcript and actual runtime/model/version/quantization settings as provenance if a local method is approved. Validate whether prompts help names without injecting words into silent or ambiguous audio. Check a Korean-specific model only if the shared model's Korean accuracy warrants the extra download and complexity.

The owner must decide whether whisper.cpp becomes a third v1 transcription method or remains research only. That choice changes the [confirmed Apple/Qwen transcription behavior](../product-behavior.md#transcription) and would require approval before dependency integration or implementation. No such selection is made here.
