# P1-M1: On-device Qwen3-ASR on iPhone 17 Pro Max

Status: Active

This research checks the local Qwen3-ASR 0.6B and 1.7B paths for the target phone as of 2026-11-01. Published device measurements establish partial feasibility, but neither model has a measured five-minute English and Korean diary comparison on an iPhone 17 Pro Max. No runtime, model, or new v1 transcription method is selected here.

## Model and runtime paths

[Qwen's 0.6B and 1.7B checkpoints](https://github.com/QwenLM/Qwen3-ASR) are Apache-2.0 speech recognition models for 30 languages, including English and Korean, plus 22 Chinese dialects. Qwen provides Python/Transformers and vLLM inference; an iOS app needs a separate conversion and runtime. Qwen's 0.6B claim of 2,000 times throughput is at 128 concurrent requests on a server, not phone latency. The separately published [Qwen3-ForcedAligner](https://github.com/QwenLM/Qwen3-ASR) is a different model, not an ASR speed or memory result.

| Path | Available evidence | Integration constraint |
|---|---|---|
| [Speech Swift](https://github.com/soniqo/speech-swift/blob/main/docs/inference/qwen3-asr-inference.md), MLX Swift / Core ML | Both sizes run in native Swift; the authors publish M5 Pro accuracy and speed for 8-bit MLX variants. The library is Apache-2.0. | Its reported Qwen speed is on a Mac, not the target phone. Its long-form path segments audio with VAD; conversion and model distribution need approval. |
| [AnySpeechRecognizer](https://github.com/mattt/AnySpeechRecognizer), Core ML | Both INT8 conversions have a Swift `SpeechTranscriber`-shaped API and iOS-compatible Core ML specification. The library and [0.6B](https://huggingface.co/mattt/qwen3-asr-0.6b-coreml) / [1.7B](https://huggingface.co/mattt/qwen3-asr-1.7b-coreml) weights are Apache-2.0. | The author tested these Qwen conversions on an M4 Max only, explicitly not on iPhone. Their decoder could not compile for the Neural Engine on that Mac; GPU execution and phone memory allowance require testing. File results cover segments up to 40 seconds; context prompts are not supported by this conversion. |
| [Core AI model zoo](https://huggingface.co/mlboydaisuke/Qwen3-ASR-1.7B-CoreAI), CoreAIKit | A published 1.7B `.aimodel` and [Swift transcription example](https://huggingface.co/mlboydaisuke/Qwen3-ASR-1.7B-CoreAI) run on iPhone and Mac, with automatic language detection. The card lists about 3.1 GB for the Mac first download. | Requires iOS 27 and the Core AI runtime; it is not a Core ML `MLModel`. The published example accepts an audio URL and converts it to 16 kHz mono samples. This exact path has no 17 Pro Max Qwen3-ASR measurement in the reviewed source. |
| [Glade 1.7B bundle](https://huggingface.co/coder543/qwen3-asr-1.7b-glade), Core AI | Another iOS 27 conversion has a measured iPhone 15 Pro Max long-recording run (below). | Approximately 2.7 GB; requires its Glade audio frontend and decoder runtime. This is a different conversion/runtime from the CoreAIKit and Core ML rows, so their timings are not interchangeable. Confirm its runtime license and integration terms before adoption. |
| [transcribe.cpp Qwen3-ASR](https://github.com/handy-computer/transcribe.cpp/blob/main/docs/models/qwen3-asr.md), GGUF/ggml | Both variants have Q8_0 files (850 MB and 2.19 GB), 16 kHz mono input, and an MIT-licensed C/C++ runtime with a Metal backend. | Published WER is on LibriSpeech, not on this iPhone. An iOS packaging and device test remains necessary. This is a Qwen3-ASR-specific runtime, not a whisper.cpp weight format. |

The existing [`.m4a` recording proposal](p1-m1-audio-format.md) therefore needs decode/resampling to the chosen runtime's 16 kHz mono input. Some wrappers accept an audio URL and do this internally; others accept only PCM or WAV. Measure that conversion in total latency and memory. A local model can transcribe offline after its files are installed, but first download, cache size, and behavior when storage is low remain product decisions.

## What the measurements establish

| Evidence | 0.6B | 1.7B | Limit |
|---|---|---|---|
| [Six-phone ASR comparison](https://huggingface.co/qvac/TranscribePsy-250M-EU), **iPhone 17 Pro Max** | 5,911 ms mean per utterance for an 8-bit Qwen3-ASR build. Set: 160 utterances / 40 minutes across eight European languages; mean of the best three of five runs. Across all six phones, Qwen's mean real-time factor was 0.462, cold start 677 ms, and peak memory at 10 seconds 1,169 MiB. | Not included. | The 5,911 ms is target-phone evidence, but the real-time factor, cold start, and memory are **six-phone averages**, not target-phone values. No Korean, five-minute clip, battery, or thermal measurement. The comparison does not identify a reusable iOS Qwen runtime or conversion. |
| [Glade 1.7B model card](https://huggingface.co/coder543/qwen3-asr-1.7b-glade), **iPhone 15 Pro Max** | Not included. | 18 min 15 s English speech processed in a 60.109 s warmed median (18.2 times real time) with 30-second chunks; 3.27 GB peak client footprint. First observed preparation of 17 assets took 270.4 s; cached load 0.43 s. | Different phone and runtime. The phone remained in a serious thermal state after compilation. Preparation is excluded from the transcription time; no Korean, five-minute clip, or energy result. |
| [AnySpeechRecognizer evaluation](https://github.com/mattt/AnySpeechRecognizer), **M4 Max Mac** | 0.94 GB model files; about 1.7 GB peak memory. | 2.36 GB model files; about 4.4 GB peak memory. | These are a *third* conversion and Mac measurements, not iPhone predictions or comparable to the two phone timings above. The author reports 0.6B at 10.5–15.4 and 1.7B at 14.5–21.2 processing minutes per hour of audio on its test sets, excluding load/compilation. |

The same [AnySpeechRecognizer evaluation](https://github.com/mattt/AnySpeechRecognizer) gives a useful **same-runtime, same-data quality comparison**: LibriSpeech test-clean utterance WER is 2.14% (0.6B) versus 1.97% (1.7B); test-other WER is 4.65% versus 3.46%. For the first 100 FLEURS Korean test files, character error rate is 5.29% versus 3.93%. On 3–8 minute English LibriSpeech files, clean/other WER is 1.68%/2.63% versus 1.58%/1.94%. The Korean score uses NFKC normalization and removes punctuation, symbols, and spaces; the recordings are read speech, not diary speech. [Qwen's own benchmark](https://github.com/QwenLM/Qwen3-ASR) also favors 1.7B on LibriSpeech, but its reference runtime and corpus differ from phone conversions.

**No reviewed source measures both sizes on the same five-minute English and Korean diary-like recordings on iPhone 17 Pro Max.** The available phone results use different devices, runtimes, audio, timing boundaries, and thermal conditions. They show that local inference is possible, but cannot establish which variant meets this app's quality, latency, memory, battery, or thermal targets.

## Physical-device comparison needed before a product choice

1. On an iPhone 17 Pro Max running the intended iOS version, test approved candidate builds of **both sizes** in Release mode. Record exact checkpoint revision, quantization, runtime version, compute unit, chunking/VAD rule, model bytes on disk, first-download bytes, cold preparation/load time, and warm load time. Run the same assets through each candidate.
2. Use consented or newly made **five-minute en-US and ko-KR diary-like recordings**, plus shorter clips and difficult cases: pauses, background noise, names, code switching, numbers, and quiet speech. Keep a human-checked reference transcript. Report English WER, Korean CER, language mistakes, missed/duplicated phrases at chunk boundaries, and punctuation separately; document the normalization rules.
3. Time from opening the recorded `.m4a` through decoding/resampling and complete transcript delivery. Report median and slow runs for cold and warm starts, peak app footprint and termination under memory pressure, storage after compilation/cache, battery/energy change, device thermal state, and repeat-run slowdown. Test airplane mode after model installation and foreground queue cancellation/retry behavior.
4. Compare these results with the approved Apple and hosted Qwen paths on the same clips. Set acceptance thresholds with the owner before any runtime or model is added to the app; [the open-decision inventory](p1-m1-open-decisions.md) remains authoritative for that choice.
