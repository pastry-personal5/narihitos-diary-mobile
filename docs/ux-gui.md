# UX GUI

Status: Active

This document defines the current interface and records owner-approved GUI behavior separately under a planned heading. Product scope is in [product-behavior.md](product-behavior.md); [UX information architecture](ux-information-architecture.md) defines containment, and [UX terms](ux-terms.md) distinguishes exact labels from concept names.

## Current interface

All has one icon-only Settings button at the top right of its root navigation bar, using the existing 24-point template gear inside a target at least 44 by 44 points. Its accessibility name is `Settings`; it opens the existing Settings screen through the state-driven route. There is no Settings list row, and child screens have normal Back navigation without an additional Settings button. Hosted checks cover compact/large bounds, light/dark appearance, and largest Dynamic Type; hands-on VoiceOver, Reduce Motion, and target-iPhone acceptance remain open in [M20 Task 6](phase-1/milestone-20-enhancements-fixes-refactoring-overview.md#task-6-move-settings-to-the-all-screen-top-right).

Settings includes a `Danger Zone` navigation item. Its scrollable screen separates Active Folder and Internal Staging, explains each irreversible scope, and uses `Purge Active Folder Contents` and `Purge Internal Staging`. First activation reveals an inline `Confirm permanent removal` heading, the explicit destructive action, and Cancel in that section; only one confirmation can be armed. Confirmation receives accessibility focus. Cancel, navigation departure, scene departure and changed folder identity disarm it. Native buttons have full-width labels and at least 44-point targets, with wrapping and Dynamic Type support. Running deletion disables both actions and reports removed-item progress. Busy work or unfinished staging explains the blocker without deleting anything; validated completed queue history does not block folder purge. Partial or interrupted deletion shows Processing Paused and requires explicit retry of that same scope; screen entry never resumes deletion. The full [Task 9 contract and evidence](phase-1/milestone-20-enhancements-fixes-refactoring-overview.md#task-9-danger-zone-purge-actions-in-settings) distinguishes simulator tests from physical iCloud verification.

The first iCloud folder selection presents `Readable Files` after choosing the folder and tapping Open. `Use Folder` commits the selection; Cancel keeps the previous folder. Validation/save errors also wait for picker dismissal so they can be presented. A picker result from a canceled, replaced, or departed selection cannot reopen the disclosure. Task 5 repairs a missing disclosure caused by dismissal arriving before the selected-folder callback; its real-iPhone selection/relaunch check on the updated app remains pending. Entering Settings does not request folder selection: All settles its Settings route before constructing the destination, and only explicit Select/Change Folder or the recording recovery gate may open the picker. Task 14's repaired target-iPhone confirmation remains pending.

The current shell includes Main, All, first-launch and Settings flows, and an M9 recording path. Main has separate 56 pt circular `en` and `ko` microphone buttons at the bottom right above the tab bar, with blue and purple backgrounds respectively and the accessibility names `Record in English` and `Record in Korean`. Tapping one carries its language into the recording gate. Main now includes the active-folder collection, local-date sections, inert read-only Diary Snippet detail, rotating notice routing through All, and custom template bitmap artwork. Favorite is currently read-only state; editing and playback remain M16. All shows typed incomplete/conflict attention without mutation actions; complete recovery presentation remains M17. Stored weather is shown only with Apple attribution material available; browsing does not reacquire recording context. The remaining v1 interface below stays in progress.

When recording output changes the active folder, Main refreshes after superseded catalog access settles and does not use `Folder Unavailable` for that internal transition. A normally finalized AAC recording also remains pending through capture inspection and Cohere conversion when AVFoundation reports a clean compressed-audio EOF. Genuine destination failure and genuinely unreadable audio retain their existing recovery states. Real-iPhone confirmation of the combined M20 report remains open.

## Planned owner-approved behavior

- The root navigation shows five tabs, labeled exactly Main, Benefits, Calendar, Plugins, and All. Their v1 empty states read “Benefits are coming later.”, “Calendar is coming later.”, and “Plugins are coming later.” respectively.
- Main shows the full active-folder diary collection with on-demand loading and infinite scroll. A one-line notice bar at its top reports queued recordings, in-app transcription activity, or recovery attention. With multiple states, it rotates one message every 10 seconds in the order processing, queued, recovery; rotation pauses for VoiceOver or Reduce Motion. Tapping a queued or processing message opens Pending Recordings; tapping a recovery message opens the relevant recovery screen. All shows no diary snippets for now; it contains a top-right icon-only `Settings` button plus entries to separate Pending Recordings, Failed Recordings, Incomplete Diary Snippets, and Conflicting Versions screens. The former bottom Settings menu item is removed. Floating `en` and `ko` Record controls appear on Main. The pending and recovery items themselves stay in their All destinations.
- Tab and control icons are monochrome custom template bitmaps with outline and filled/state variants at 1x/2x/3x and system tint. Use conventional metaphors for Home, Benefits, Calendar, Plugins, All, microphone, stop, settings, pending, warning, incomplete, conflicts, favorite, play, pause, and seek. Use 25 pt tab art, 24 pt inline/control art, and 32 pt Record/Stop art inside targets of at least 44 by 44 pt. No Main Toolbar is specified.
- Pending and Failed Recordings stack recovery actions vertically as full-width buttons within each entry. Retry, Retry Verification, Resume, and Choose Method use filled accent surfaces; Remove uses a tinted destructive surface. Centered headline labels have a minimum height of 52 points and wrap for larger text; retain safe horizontal list margins and 12-point spacing between actions. Inline removal confirmation remains inside the entry.
- The Diary Snippet collection groups entries by the recording-start instant in the user's local calendar and shows an automatically generated, read-only title.
- A completed Diary Snippet saves automatically with an Apple on-device AI title summarizing the whole diary body when available, or an ellipsized first-sentence title if the model is unavailable or returns an empty or failed result. Both have a strict maximum of 30 Swift extended grapheme clusters, including the ellipsis. AI title failure does not delay saving. Its managed diary body starts as the transcription output. There is no pre-save review step or separate original-transcript view.
- An AI title follows the current diary body's language, which can differ from the recording language after editing. A wrong-language result uses the fallback. Long-body summarization must consider all parts within bounded work or use the first-sentence fallback; an AI title over 30 displayed characters is truncated locally with an ellipsis. A saved fallback title stays until the next body save, even if the model becomes ready meanwhile.
- [M20 Task 2](phase-1/milestone-20-enhancements-fixes-refactoring-architecture.md#task-2-dedicated-transcription-settings-and-model-choices) moves Apple/Cohere controls into a dedicated `Transcription` screen, reached by the `Transcription` group/card/item in Settings. Its `AI Models` choices are exactly `None`, `Apple Local`, `Cohere Q4`, and `Cohere Q5`, with selected-model details and separate selection/install intents. Parent Settings summarizes the saved choice/readiness. None or an unready preference leaves unclaimed recordings pending without fallback; existing capture gates still apply. Pending/Failed Recordings → Choose Method reaches the same screen with its language context and requires a ready recovery choice; failed work still needs Retry. Q4 and Q5 show separate pinned sizes/readiness and never share installation state. Hosted Qwen controls remain outside v1.
- [M20 Task 16](phase-1/milestone-20-enhancements-fixes-refactoring-architecture.md#task-16-apple-local-transcription-failure) requires Apple Local readiness to include the app's locale reservation, not only a system-installed asset. An installed but unreserved English or Korean asset shows `Setup required` with a `Set Up … Model` action; recordings remain pending until setup succeeds, and the app does not claim an Apple attempt that SpeechAnalyzer would reject as unallocated.
- If Apple on-device transcription is unavailable for a queued recording, explain why and ask the user to choose an available approved method. Do not switch methods automatically.
- While the app is open, queued recordings transcribe from oldest ready to newest ready; a waiting item does not block newer ready work. Pending and failed recordings have visible states, and a failed item offers manual retry. Both screens let the user remove an entry and its private audio after confirmation. Remove expands a confirmation inside that entry, retaining its date/language/reason context and showing vertically arranged Remove Recording and Cancel buttons; no overlay dialog appears. Only one entry is armed, and Cancel, leaving the screen, scene departure, or a disappearing/Cancelling entry clears it. Removing an in-flight item shows Cancelling until its work stops and removal completes. An already verified asset remains saved if completion won the race before removal confirmation; explain that outcome. A job restored from an older device backup appears in Pending Recordings as “Restored—review required” with Resume and Remove; Resume uses current Settings.
- Pending recordings and failed recordings have separate screens, opened from All.
- A Failed Recordings entry shows the reason when transcription produced no usable words and offers manual retry; no Diary Snippet is created for that result.
- Manual transcription retry uses the method and settings current at retry time and has no fixed count limit while the recording remains.
- Stop & Transcribe is the only user control during capture; it stops and queues playable audio for automatic processing while the app is open. Locking the iPhone does not stop capture. Recording stops and queues automatically at five minutes. A playable partial recording queues automatically after an interruption; show the resulting pending item. An unplayable partial appears in Failed Recordings with its reason. Pause/resume and discard controls are outside v1.
- V1 requests notification permission for a local reminder on the next local day at the same local time the user left if transcription remains pending. Cancel it if all pending work finishes before delivery. If permission is denied, keep pending work visible and provide a nonblocking system Settings path without repeated prompts. The reminder cannot be treated as guaranteed delivery.
- If a pending recording is saved into a former active folder, show a dismissible nonblocking banner for six seconds: “Diary saved to {folder}.” Announce it politely with VoiceOver and use no motion under Reduce Motion. If its destination is unavailable, show that the result is pending and ask the user to restore access.
- Require an iCloud folder choice before the first recording. Ordinary provider/network failures leave the original destination pending. If the user confirms its folder was removed or access was revoked, let the user explicitly choose a replacement for the affected pending recording.
- First launch explains and requests microphone permission for recording. If denied, the rest of the app remains usable, and Record shows a route to system Settings instead of starting capture. First launch also asks for optional location permission, and Settings offers a control for later location permission changes; location denial does not block recording.
- Recorded-audio replay offers play/pause, seeking, and elapsed and total time. Accessibility labels are `Play audio`, `Pause audio`, and `Audio position`; the value is `{elapsed} of {total}`, and the position is adjustable in 15-second steps.
- Diary Snippet detail presents the Title and Diary body first, with Favorite beside the Title. Metadata is at the bottom and contains Audio replay plus read-only recording start date/time, duration, recording language, and available place and weather. A geocoding failure displays raw coordinates without a place name. Display weather using the system measurement locale and put Apple Weather attribution beneath it. Omit unavailable fields. Title provenance remains hidden.
- Keep title-generation origin and version details in Markdown front matter without displaying them in Diary Snippet detail. Incomplete Diary Snippets contains incomplete pairs, safe unsupported assets, malformed required v1 assets without repair copies, and legacy Markdown with zero or multiple plausible audio files. Preserve and show each read-only with its reason; offer confirmed removal only where ownership and containment are verified. Conflicting Versions presents one version per tab when iCloud modification times are equal, missing, or cross-ordered; each tab scrolls vertically. Tabs are labeled `Version 1` and `Version 2`, with the modification date as the accessibility value when available. After the user selects a version, confirm before removing the other. An unambiguously later whole pair is selected automatically; obsolete-version removal follows verified publication and both upload reports.
- The editor changes only the diary body. Saving regenerates the title using the same AI-or-fallback policy; the title has no direct edit control. Favorite has an on/off toggle.
- Visible control labels are their accessibility names; icon-only controls use the canonical action. Favorite and playback expose state or value without redundantly saying “button”. Main notice rotation pauses for VoiceOver, and each newly appearing notice state receives one polite announcement. Screen headings use the exact destination label, `Diary Snippet`, and `Edit Diary`; capture adds no extra heading.
- Render diary Markdown as inert native content. Links are not interactive in v1, and HTML, scripts, remote images, and automatic fetches are disabled.

The closed [decision inventory](research/p1-m1-open-decisions.md) records the P1-M5 handoffs. The [initial ideas](research/initial-ideas-from-owner.md) contain additional proposals that have not all been approved.

## P1-M4 design review boundaries

- Main owns the active-folder Diary Snippet collection; All owns Settings, two recording-status destinations, and two recovery destinations. A recording awaiting save or retry is distinct from a completed Diary Snippet.
- The structure in [UX information architecture](ux-information-architecture.md) does not decide the visual style of navigation. Icon art, accessibility names, and completion notice presentation need review before implementation.
