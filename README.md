# Narihito's Diary Mobile

An iPhone app that creates personal data assets from other multimodal data.

V1 plans offline transcription with Apple on-device speech and an on-device Cohere Transcribe model. The selected Cohere integration direction uses the pinned Q4_K_M model with `transcribe.cpp` and Metal; production integration remains in progress. Hosted Qwen transcription is planned for future work.

The first-time experience requests microphone access for recording and optional When In Use location access. Other parts of the app remain available if either is denied. Before recording, the user selects an iCloud Drive folder; the current boundary fails closed unless the folder passes iCloud metadata and account-identity checks, with target-device provider verification still in progress.

Each recording becomes a Markdown diary entry paired with its audio. Transcription initializes the diary text, and later edits replace that text; the app does not keep a separate original transcript. A read-only title summarizes the diary on device when Apple's model is available, with a shortened first-sentence fallback.

For the first folder selection, choose Select Folder, pick an iCloud folder, and tap Open. The Readable Files dialog then offers Use Folder to save the selection. Settings retains the folder and transcription choice across reopening; a failed save keeps the previous settings. Opening Settings no longer shares its activation with the Change Folder control, so it does not open the folder picker by itself. The M20 folder repairs have simulator coverage; verification of the updated app through Files on the real iPhone remains pending.

M20 also repairs two transcription failures: recording checks preserve an active transcription's audio-file metadata, and Cohere recognizes the verified Metal device even when the runtime names its backend `MTL0`. The latter cause was traced on the real iPhone; regressions, lint, and the full simulator gate pass. Retrying the failed recording on the updated phone now creates a diary; fresh-capture/relaunch confirmation remains open. Cohere Q4/Q5 whole-file trust verification now runs away from the UI/main actor, repairing a phone-proven watchdog termination after Q5 transfer. Later phone launches proved the old `FileHandle` loop could still be jetsammed while rehashing the installed Q5 artifact, even with inference denied; verification now feeds SHA-256 from one reusable POSIX buffer. Q5 stays installed but runtime preflight fails closed pending exact-path device certification, preserving recordings with a choose-another-ready-method wait and leaving Q4 unchanged. The final phone build remains running after Q5 readiness verification, and focused tests, lint, and the full simulator gate pass.

In Pending and Failed Recordings, Retry and Remove are large, full-width buttons. Remove expands confirmation inside the selected entry; choose Remove Recording to proceed or Cancel to keep it.

The pending-recording performance repair reuses checks of unchanged audio and avoids preparing playback during list refreshes. Queue readiness checks are shared while pending, and recordings continue to transcribe one at a time. Target-iPhone confirmation with six pending recordings remains open; see [M20 Task 18](docs/phase-1/milestone-20-enhancements-fixes-refactoring-overview.md#task-18-app-becomes-slow-with-multiple-pending-recordings).

## Development

The app uses a flat journal icon; its editable vector source is in `assets/app-icon/`.

The SwiftUI app currently includes the five-root navigation shell, first-launch permission flow, Settings foundation, persistent iCloud-folder selection boundary, recording and local recovery, and a durable foreground processing queue. Main has separate blue `en` and purple `ko` recording buttons at the bottom right. Each starts capture in its indicated language; Stop & Transcribe stores a pending local recording. Pending work is bound to the current installation, and restored work requires explicit Resume or Remove. Settings supports explicit Apple method selection and system-model installation progress. Cohere model installation, readiness, explicit selection, and local transcription are being integrated; their simulator and target-iPhone validation remains open. Verified transcription now becomes a protected local diary draft; the iCloud save path is being completed and retains private staging while per-file upload proof is missing. A verified save to a folder that is no longer active shows a dismissible six-second completion banner. Removing a pending recording also cleans its identified private conflict copies. Main now discovers and pages validated diary entries from the active folder, groups them by local recording date, and opens read-only text and recording metadata. Existing timestamp-named legacy pairs remain read-only and unchanged. A notice bar routes pending/recovery attention through All, with rotation paused for VoiceOver or Reduce Motion. Full editing, playback, and incomplete/conflict recovery actions remain later work; M15 target-iPhone browsing/provider/accessibility evidence remains open. Target-iPhone lock, background, interruption, file-protection, and backup/restore trials remain open. With Xcode 27.2 or later and XcodeGen installed, run `make generate` to create the Xcode project, `make build` to generate and build it for the iOS Simulator, or `make open` to generate and open it in Xcode. Generation selects the first development team available in Xcode without committing its Team ID. Use `TEST_DESTINATION='platform=iOS Simulator,name=<available iPhone>' scripts/validate.sh` for concise generation, lint, build, and test results. The app requires iOS 27.0.1 or later.

Post-save catalog refreshes now wait for superseded catalog work, and a stale page caused by the app's own diary write starts a bounded fresh traversal instead of showing `Folder Unavailable`. Late callbacks from an old folder presenter cannot invalidate the replacement session. Finalized AAC inspection and Cohere conversion accept AVFoundation's typed clean end-of-file after decoded audio while still rejecting empty, changed, malformed, or truncated sources. These M20 repairs have simulator regressions; their combined Files/recorder/Cohere behavior still requires the documented real-iPhone check.

The Settings flow now has a dedicated Transcription screen with explicit None, Apple Local, Cohere Q4, and Cohere Q5 choices. Selection is persisted separately from readiness; Q4 and Q5 use independently pinned local model installations and never switch automatically. Apple Local also verifies that an installed language model is reserved for this app: an installed but unreserved language shows Setup required until its setup action completes. A target-iPhone recording fix now applies private-file attributes before preparing the AAC encoder, preventing long captures from collapsing to an empty encoder-priming file. Spoken Apple diary/relaunch acceptance and long-input production evidence remain tracked separately.
